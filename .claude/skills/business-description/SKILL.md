# business-description — 技术语言→业务语言翻译

## 持久性

**一次性。** 本次翻译只对当前回复生效，不改变后续对话风格。如需持续业务语言模式，使用 `/i-have-adhd`。

## 翻译规则

### 1. 术语锚定

术语必须对齐项目已有的菜单/功能名称。不确定时保持模糊，**禁止补充未经确认的业务场景**。

| 正确（有锚点） | 错误（无锚点） |
|----------------|----------------|
| 出入库流水记录 | 库存变更日志 |
| 库存盘点单 | 库存核对表 |
| 库存总览 | 库存看板 |

❌ 反面教材：`"可能是生产模块的投料功能"` → 违法（加了"投料功能"的猜测）  
✅ 正确做法：`"与生产模块有关"` → 保持范围模糊

### 2. 三段式翻译模板

```
技术概念 → 业务含义 → 用户可感知的影响
```

每一段用一句中文说清，不嵌套技术细节。

### 3. 禁止项

- ❌ 文件路径（`c_mes_inventory_ledger`、`jeecg-boot-module/...`）
- ❌ 类名/方法名/API 名（`MesStocktakeController`、`defHttp`）
- ❌ 未确认的业务场景推断（"这应该是盘盈盘亏的原因"——除非上下文明确说了）
- ❌ 开场白（"好的我来翻译一下"、"这段技术内容的意思是..."）
- ❌ 结束语（"希望这能帮到你"、"有需要随时问"）

### 4. 输入来源（无参模式）

取上一条 `assistant` 角色消息的纯文本内容，跳过 `tool_use`/`tool_result` 块。若上一条是工具调用（无文本），向上回溯到最近一条有文本的 `assistant` 消息。

## 示例

**输入**（技术回复）：
> `c_mes_inventory_ledger` 加了 `remark` 列，`stockIn`/`stockOut` 方法签名重载向后兼容。SQL 迁移文件 V9.9.2。

**输出**（业务翻译）：
> 出入库流水记录新增了"备注"字段，入库和出库操作现在可以附带原因说明。已有的老数据不受影响，不需要额外处理。

**输入**（技术回复）：
> `defHttp` 拦截器在收到 `successMessage` 时自动弹出顶部横幅通知，与手动设置的 `message.success` 冲突，导致审核后出现两条重复提示并触发滚动。

**输出**（业务翻译）：
> 审核操作完成后，成功提示出现了两条：一条是系统自动弹的，一条是页面自己加的，两条撞在一起导致提示区闪烁滚动。修完后只保留一条，审核完成时页面顶部会干净地显示一次成功确认。
