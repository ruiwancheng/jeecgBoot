# /gen-tests <项目名> <功能名>

**每次运行都重新生成**，覆盖已有测试文件。根据最新代码 + 自定义推导规则重新生成 API 和 E2E 测试用例。

## 用法
- `/gen-tests demo 仓库管理` — 为仓库管理生成 API + E2E
- `/gen-tests demo` — 为 demo 项目所有功能生成

## 流程

使用 `gen-tests` 技能获取：环境初始化命令、Playwright 配置模板、API/E2E 推导规则、测试目录结构、调用链覆盖扩展参数、自定义规则合并逻辑。

### 1. 加载领域知识

按技能文件获取全部技术细节。

### 2. 覆盖缺口分析（可选增强）

使用技能中的调用链覆盖参数调用 MCP graph tools。
- 图形可用 → 追踪 Controller→Service 调用链，发现未覆盖 hub 节点
- 图形不可用 → 仅覆盖 Controller 端点（标准降级）

### 3. 生成 API 测试

按技能推导规则从 Controller 方法生成 → 输出到技能定义的目录。

### 4. 生成 E2E 测试

按技能推导规则从前端配置生成 → 输出到技能定义的目录。

### 5. 断言语义深度自检（2026-08-04 新增）

按 R009 规则自检生成的测试文件：

1. **数量门控**：每个 .test.js 必须 ≥ 2 个 c.check/expect/assert 断言
2. **深度门控**：每个场景必须 ≥ 1 条语义断言（字段值/状态流转/显示值/数据传递）
3. **不达标处理**：
   - 数量 < 2 → 拒绝写入，提示"断言密度不足"
   - 语义断言缺失 → 警告但不阻塞，列出缺失场景

详见 `gen-tests` 技能"断言语义深度校验（R009）"章节。

### 6. 告知结果

生成了哪些测试文件、API 覆盖了几个接口（标注自定义规则命中数）、E2E 覆盖了几个场景、断言密度自检结果。
