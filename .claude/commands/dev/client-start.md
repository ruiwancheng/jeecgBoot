# /client-start

启动**客户端全栈开发环境**。每个客户端是独立完整的本地开发服务器。

与 `/start` 的区别：`/client-start` 额外启动 MCP 工具链（code-review-graph 知识图谱 + Orca CLI）。

## 用法

说明："启动客户端"、`/client-start` 即可启动；"帮我停止开发环境"停前后端（MySQL/Redis 保留）。

## 流程

使用 `client-start` 技能获取：初始化流程、MCP 配置、标记文件路径、就绪确认模板。

### 1. 检测运行阶段

- 检查技能中定义的标记文件是否存在 → 决定是首次接入还是快速检查
- 首次接入时引用 `onboard` 技能做工具链核查

### 2. 全栈启动

复用 `local-dev` 技能的流程（与 `/start` 相同）：环境检查 → 数据库初始化 → 安装前端依赖 → 启动后端 → 启动前端。

### 3. MCP 工具链

增量更新知识图谱 + 检查 Orca 状态 → 按技能中的就绪模板输出确认信息。

## 停止

"帮我停止开发环境" → 停止前后端（MySQL/Redis 保留）；"全部停止" → 全部停止。

## 与其他命令的关系

| 命令 | 全栈启动 | MCP 工具链 | 适用场景 |
|------|:--:|:--:|------|
| `/start` | ✅ | ❌ | 服务端/单人开发 |
| **`/client-start`** | ✅ | ✅ | **多客户端开发，需要代码审查/知识图谱** |
| `/onboard` | ❌ | ❌ | 仅检测工具链，给安装指引 |

## 故障自愈

- 标记文件/配置/依赖被误删 → 自动检测并重建
- 图谱构建失败 → 不阻塞启动，稍后可手动 `/update-graph`
- MCP 未连接 → 提示重启终端使配置生效
