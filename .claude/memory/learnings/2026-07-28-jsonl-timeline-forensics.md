# [2026-07-28] [方法论] 用 Claude Code 会话 jsonl 做故障时间线取证

## 触发条件
"某功能一直不正常"类排查，需要确定故障起点和诱因（如"Orca 可用但钩子一直误报不可用"）。

## 方法（本次实证）
1. **会话记录位置**：`~/.claude/projects/<项目路径转义>/*.jsonl`，每会话一个文件
2. **按内容 grep 而非按文件名排序**：文件 mtime 是"最后活跃时间"，但钩子输出反映的是"会话开始时间"——长会话的 mtime 会造成时间线错觉（本次一个 07-25 的"可用"记录实为 07-24 下午开始的会话）
3. **grep 钩子输出原文**（如 `Orca: 可用/不可用`）逐会话统计，画出好坏时间线
4. **关联环境变更时间点**：二进制文件的安装时间戳（`ls -la claude.exe`）、`git log` 相关文件提交时间，与故障起点对齐
5. **区分真实输出 vs 文件内容**：grep 计数会混入"读到含该字符串的文件"，要看上下文确认是钩子真实输出

## 效果
10 分钟定位"07-24 18:09 Claude Code 更新 → 钩子环境变化 → python3 stub 命中"的完整因果链，避免了盲猜。
