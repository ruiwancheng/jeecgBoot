# 代码事实查证优先——评审不信任计划的表名/字段/调用点声明

**触发条件：** 收到任何实施计划，其中包含"X 表有 Y 列"、"N 个 Service 调用 Z 方法"、"状态值是 'IN_PROGRESS'"等具体声明。

**处理方式：**
1. 打开计划声称引用的源文件，逐项核对字段名、表名、状态值、调用次数
2. 用 grep 验证调用点数量（计划说"4 个 Service 调 createBatch"→ grep `\.createBatch\(` → 实际 3 个）
3. 对状态枚举值，查 DDL 的字典定义或 Entity 的 `@Dict` 注解——不依赖计划中的文本描述
4. 发现不一致立即标记 P0，附实际代码行号作为证据

**实证：** 2026-08-01 连续两轮评审中，批次总开关评审发现 L2 `status='IN_PROGRESS'` 在 DB 字典中不存在（实际 '1'/'2'/'3'/'4'），L3 假设业务表有 `batch_id` 列但实际通过 `origin_bill_id` 反向关联；批次手工录入评审发现计划声称"4 个 Service"实际仅 2 个调 `createBatch`。两轮共 3 个 P0 全部来自"代码事实与计划声明不一致"，而非逻辑设计错误。
