# [2026-07-28] [验证] JeecgBoot 接口验证不能只看 HTTP 码——200 里包着 404

## 触发条件
新模块写完，curl 探测接口是否存在。

## 现象
`curl -w "%{http_code}"` 返回 200，以为 Controller 已加载；实际 body 是 `{"success":false,"code":404,"message":"路径不存在"}`——JeecgBoot 的 Shiro 过滤链对未注册权限的路径返回 **HTTP 200 + body 404**。新类也未被 DevTools 热载（spring-boot:run 下新 Controller 需要 install + 重启才生效）。

## 正确处理
1. 接口存在性判断看 body 的 `success` 字段，不看 HTTP 码
2. 权限是否注册直查数据库：`SELECT id, perms FROM sys_permission WHERE perms LIKE 'mes:xxx%'`
3. 新增 Java 类后要实测新端点前，先 `mvn install -pl <模块>` + 重启后端，别信 DevTools 热载（它只覆盖已有类的修改）
4. 权限缓存：部署后非 admin 角色看不到新菜单是常见事故 → 交付前必须用业务账号验证
