# 僵尸命令判定清单：命令文档 ≠ 可用功能

**触发**：用户问"这个命令是干什么的/有价值吗"，或盘点 harness 命令时。

**判定清单（4 问全中 = 死命令）**：
1. **有无可跑资产？**（如测试命令 → 项目有无可跑的测试文件/套件）
2. **技术栈是否匹配？**（技能写 `npx vitest run`，项目实际是 node 脚本/Playwright → 模板没适配）
3. **有无引用方？**（grep hooks/CI/其它命令是否调用它）
4. **实践是否触发过？**（近期开发流程是否自然用到）

**处理方式**：
- 全中 → 删命令文件 + 清理 skill/索引引用，commit 说明原因（/test-loop 实例）
- 部分中 → 保留但加警告或改造适配实际资产

**延伸**：test-all 技能写 `npx vitest run harness/tests/*.spec.ts`，项目实际是 `node harness/tests/*.test.js` ——同类错位，技能文档需要跟随资产形态修正。

**价值**：harness 治理的通用判据，避免"文档看起来很美"的命令误导使用者。
