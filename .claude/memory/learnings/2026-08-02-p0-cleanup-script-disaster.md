# 批量删除脚本破坏文件 + git reset 救场

**日期**：2026-08-02
**类别**：P0 清理 / 脚本安全
**触发条件**：
- 大规模执行"删除未使用变量/import"等破坏性脚本（>100 个文件）
- 脚本没有试运行（`--test`）机制
- 没有按文件分批验证
- 没有事先 git commit 作为回退点

**处理方式**：

1. **强制先试运行** — 任何修改文件 >50 个的脚本，必须先 `--test` 参数跑一次，统计修复数
2. **限制单次批量** — 一次只处理一个子目录或一类错误（`grep "error TS" | head -100`）
3. **每批验证** — 每批跑完跑 `npx vue-tsc --noEmit`，**看总错误数是降是升**
4. **保留回退点** — 每次 commit 完成后记录 commit hash
5. **错误数比修复前多就立刻回退**：
   ```bash
   git reset --hard <last-known-good-commit>
   ```

**耗时损失**：约 2 小时本可以做更多有意义的事，最终回到原点。

**关键错误**：

1. ❌ 没有先 `--test` 跑试运行
2. ❌ 一次性跑全 1025 个错误，没有按文件分批
3. ❌ 跑完没立即验证（跑 `npx vue-tsc` 看错误数变化）
4. ❌ 验证发现错误数从 1 → 1180 时没有立刻停止
5. ❌ 继续修"破坏性副作用"（fix-ts6133 第二轮跑空标识符修复），把问题扩大

**正确流程**：

```bash
# 1. 先试运行
python fix-script.py --test

# 2. 试运行 OK 后小批（一次 50 个文件）
python fix-script.py | head -50  # 限制

# 3. 每批验证
npx vue-tsc --noEmit  # 错误数应该下降

# 4. 错误数上升就回退
git reset --hard HEAD

# 5. 重新设计策略（更保守的脚本 / 人工 / 跳过）
```

**适用场景**：
- 删除未使用变量/import
- 批量重命名
- 批量格式化
- 自动修复 lint 错误
- 任何会改 ≥50 个文件的脚本
