# 存量 E2E 修复顺序：先通登录闸门，真失败才会浮现

**触发**：一批老 E2E 全挂或部分挂，需要修复时。

**规律**：登录是闸门——登录注入错误时，所有用例都死在第一步（页面跳登录页），下游的选择器漂移/断言过时被掩盖，表现为"全是同一个错"。

**正确顺序**：
1. 先把登录抽成公共 helper 并修通（本次：双层包装 token 注入）
2. 全量跑一遍——此时失败数可能"变多"（本次 1 挂 → 3 挂），别慌，这是被掩盖的真失败浮现
3. 按错误分类逐个修内容漂移（选择器/断言/组件模式）

**反模式**：登录不通时就去修某个用例的选择器——修好也验证不了，因为根本到不了那一步。

**配套判断**：失败全在同一步（如登录后第一断言行）→ 先查登录/导航；失败分散在不同步骤 → 内容漂移逐个修。

**实证**：harness/mes E2E 从"1 挂（疑似按钮改名）"→ 修登录后"3 挂（真因：radio/checkbox、空格按钮、500 脆弱断言）"→ 修完 12/12 全绿。
