# 大任务垂直切片方法论（页面顶层 + 子功能细分）

**场景**：用户开发 JeecgBoot 业务模块时，遇到大型任务管理痛点——单次 brainstorm/plan 把整个大功能塞进上下文，token 暴涨触发限制；多 worker 并发改同模块还会搞崩开发环境（Maven 编译锁死、DevTools 热重载叠加 OOM、Vite 缓存污染）。最初尝试按"后端到前端"分层切（Entity→Service→Controller→Vue），但中途处于"啥也看不到"状态，无法手工验收。

**核心洞察**：**每个切片 = 一个端到端可手工走通的最小业务场景。** 用户能在浏览器里点一遍看到结果，才能把控质量。

**两级切片结构**：

```
顶层切片（页面级）
├── 页面 1：订单列表页（complex）
│   ├── 子切片 1.1：列表展示+新建（最小闭环，可立刻验收）
│   ├── 子切片 1.2：编辑订单
│   ├── 子切片 1.3：作废订单
│   └── 子切片 1.4：审核订单
└── 页面 2：订单详情页（complex）
    ├── 子切片 2.1：物料明细展示
    └── 子切片 2.2：物料编辑
```

**粒度判断规则**：

| 页面复杂度 | 处理 |
|----------|------|
| simple（每页 1 个功能，如字典管理） | 顶层 1:1 对应子切片（不细分） |
| complex（每页多个操作，如订单列表页含新建+编辑+作废+审核） | 顶层 + 子功能细分 |

子功能粒度：
- ≤5 行代码变化 → 必须合并到相邻子功能
- 6-50 行 → 独立子功能
- >50 行 → 警示，可能需要再拆

**6 要素拆分原则**（每个子切片必须包含）：
1. 业务名 + 用户操作路径（浏览器打开 → 操作 → 看到结果）
2. 验收标准（UI 上能看到什么，**禁止** "Service 返回 X"）
3. 依赖关系（其他切片 ID，禁止循环）
4. 风险等级（高=Entity/SQL/状态机；中=Service/Controller/加字段；低=Vue/文案）
5. 工作量估算（小 ≤20 行；中 21-100 行；大 >100 行）
6. Rollback 策略（commit 锚点 + `git revert` 命令）

**8 条反模式**（必须主动警告）：
- ❌ 先做完所有 Entity（用户看不到结果）
- ❌ 先做完所有 Service（没 Controller 调用 = 白做）
- ❌ 先做完所有 Vue 列表（没增删改 = 花瓶页面）
- ❌ 先做完所有后端接口（没前端 = 不可用）
- ❌ 按代码文件类型分片（任何一片都跑不通）
- ❌ 全建表（一次性建好所有 Entity）
- ❌ 按菜单结构切（菜单层级 ≠ 业务场景）
- ❌ 先做权限（权限依赖功能完成）

**Token 成本控制**：

| 切片规模 | orca-review 模式 | Token |
|---------|-----------------|-------|
| ≤3 文件 | 免评审 | 0 |
| 4-10 文件 | 轻量评审 | ~30K |
| >10 文件 | 完整评审 | ~150K |

> 评审成本预估要写在每个切片输出里，让用户决策。

**实证**：2026-07-31 `/decompose` 命令落地（`.claude/commands/dev/decompose.md` + `.claude/skills/decompose/SKILL.md`）。含 6 要素拆分、8 反模式、粒度判断、状态持久化（`.claude/.decompose-state.json`）、与 `/plan` 自动衔接。

**避免**：
- 看到"复杂任务"就按"层"切（Entity→Service→Controller→Vue）—— 切片 1 完成后用户啥也看不到
- 子切片写"Service 返回 X"作为验收标准（用户看不到）
- 首个切片无法跑通最小闭环（用户立刻失去信心）
- 复杂页面（如订单列表页）整页作为 1 个切片（违反"端到端可手工验证"）

**关联命令**：
- `/decompose <大任务>` — 输出切片清单 + 状态文件
- `/decompose`（无参数）— 检测状态文件，进入"继续模式"
- `/decompose --no-cache` — 忽略 plan 缓存，使用输入参数
- `/decompose --restart` — 备份旧状态，重新切片

**判断信号**：
- 用户说"任务太大"、"token 爆了"、"环境崩了" → 触发垂直切片
- 大任务含 ≥3 个页面或 ≥10 个文件改动 → 触发 `/decompose`
- 单页面简单 CRUD → 不需要切片，直接走标准工作流
