# 自定义查询接口"传了不认"：参数静默忽略是最坑的接口行为

**场景**：库存总览自定义联表查询只支持 keyword/warehouseId，前端传 `materialId` 被**静默忽略**——每次查询都返回仓库第一行，导致盘点抽盘账面数全部错成同一个值。

**为什么坑**：
- 接口返回 200 且数据"看起来像对的"（有值、格式对），没有任何报错信号
- 调用方恰好用第一行物料验证时（MAT-DBG1），结果"碰巧正确"，掩盖问题
- 只有用第二、三个不同值验证才暴露

**排查/预防方法**：
1. **造 3 个可区分的值**（库存 11/22/33）——一次调用就能判定"参数是否生效"：全相同=参数被忽略
2. 自定义查询接口在代码注释里**显式列出支持的参数**，前端调用前对照
3. 加参数时用"可选过滤"模式：`AND (i.material_id = #{materialId} OR #{materialId} IS NULL)`（向后兼容）

**同类警示**：QueryGenerator 接口默认支持实体字段过滤，自定义 SQL 接口则**一个参数都不自动支持**——两类接口的过滤能力完全不同，混用必踩。

**实证**：2026-07-29 盘点账面数 bug（MAT-DBG2 传参返回 MAT-DBG1 的值）。
