# 01_风控总报告 — MES 财务模块（会计科目/应收账款/应付账款）

> **审计时间**：2026-07-19
> **审计对象**：JeecgBoot MES 业财管控模块（Phase2 Step3 MVP）
> **代码范围**：3 子模块 × 5 类后端（15 个 Java）+ 10 个前端文件 + 1 个 SQL + 2 个业财联动 audit hook + 菜单注册
> **审计团队**：铁拳团 10 人（3 产品 + 3 研发 + 4 测试）
> **报告结构**：01 总报告 / 02 成员产出统计 / 03-12 专项报告 / index.md

---

## 一、总体结论

| 维度 | 评分 | 说明 |
|:---|:---:|:---|
| 架构规范性 | ⭐⭐⭐⭐ | JeecgBoot 三层架构 100% 标准，命名/权限/字典/全家桶复用规范 |
| 功能完整性 | ⭐⭐ | **只读流水展示页**，财务核心闭环（收付款/核销/凭证/红冲）缺失 |
| 数据正确性 | ⭐ | **应付金额恒为 0**，销售出库取单价 `items.get(0)`，税率全链路缺失 |
| 资损风险 | ⭐ | 高：金额错误传染 + 无幂等 + 无对账 + 无红冲 |
| 并发安全 | ⭐⭐⭐ | `auditWithGuard` 原子 UPDATE 可靠，但 `source_bill_id` 无唯一索引 |
| 性能 | ⭐⭐⭐ | 基座防护到位，但应收/应付缺索引，主子表逐行 INSERT |
| 部署可用性 | ⭐ | **SQL 不在 Flyway 扫描路径**，客户部署时表根本建不起来 |

**一句话结论**：这是一个**"骨架优秀但无法交付"的 MVP**——业财联动的链路通了（出库审核自动生成应收/应付），但**应付金额是错的、收付款功能没有、凭证模块是空壳、SQL 不会被自动执行**。当前状态交付客户，等于给客户一个"会自动产生错误数据且无法修正"的记账本。

**综合评分：5.5 / 10** —— 不建议以当前状态交付真实客户。

## 二、共识 P0 风险清单（必改，14 项）

> 以下 P0 均经主控 grep/read_file 复核属实，按业务影响排序。

### 🔴 资损类（最高优先级）

#### P0-1 应付单金额恒为 0（资损实锤）
- **代码位置**：`MesPurchaseReceiptServiceImpl.java:132`
- **现状**：`ap.setAmount(BigDecimal.ZERO)`，注释自承"MVP 待价格模块完善后自动计算"
- **影响**：客户看到的应付台账全是 ¥0，无法回答"欠供应商多少钱"；**业务上等同记账失败**
- **根因**：入库明细表无 `unit_price`/`amount` 字段
- **修复**：入库明细补 `unit_price` 字段，从采购订单行带出；`audit` 时 `amount = Σ(receiptQty × unitPrice)`
- **识别成员**：03/04/05/06/12（5 票）

#### P0-2 销售出库取单价用 `items.get(0)`（多行同物料错价）
- **代码位置**：`MesSalesOutboundServiceImpl.java:227`、`MesDeliveryNoteServiceImpl.java:173`
- **现状**：同物料多行订单（不同批次/让利价）时取首行价，错误传染 `totalAmount → receivable.amount`
- **修复**：明细行补 `order_item_id` 外键，按行取价；或按物料加权平均价
- **识别成员**：05/12（2 票）

#### P0-3 税率全链路缺失（应收是否含税口径不明）
- **现状**：只有采购订单内部算税；入库→应付断链；销售订单/发货/出库/应收全无税率字段
- **影响**：财务不知道应收金额是否含税，无法开增值税发票
- **修复**：销售订单行补 `tax_rate`/`tax_amount`；应收单补 `tax_amount`/`net_amount` 字段
- **识别成员**：05/12（2 票）

#### P0-4 收付款闭环完全缺失（应收/应付永远无法结清）
- **现状**：`MesReceivableServiceImpl`/`MesPayableServiceImpl` 各 13 行空壳；Controller 无收款/付款/核销端点；前端页面只有"导出"按钮
- **影响**：`received_amount`/`paid_amount`/`status` 是死代码，单据生成即终态
- **修复**：补收款登记/付款登记 API + 前端弹窗；状态机 `1未结清 → 2部分结清 → 3已结清`
- **识别成员**：03/04/06/07/12（5 票）

#### P0-5 无反审核红冲（错误数据无法修正）
- **现状**：`cancel()` 只改状态，不回补库存、不冲应收/应付；全库 0 命中红冲关键字
- **影响**：出库单审核错了，库存和应收都回不去，财务只能手工改库
- **修复**：`cancel()` 联动红冲（库存回滚 + 应收/应付标记作废或红冲负单）
- **识别成员**：05/08/12（3 票）

### 🔴 数据一致性类

#### P0-6 应收/应付 `source_bill_id` 无唯一索引（重复审核产生重复财务单）
- **现状**：SQL 仅 `uk_rec_code_del (code, del_flag)`，`source_bill_id` 裸奔；AR code 含日期 `AR-yyyyMMdd-code`，跨天重复审核会生成重复 code
- **影响**：极端并发/重试场景下，同一出库单生成多张应收单 → 资损
- **修复**：`c_mes_receivable`/`c_mes_payable` 补 `UNIQUE INDEX uk_source_bill (source_bill_id, del_flag)`；AR/AP code 去日期改为 `AR-单号`
- **识别成员**：06/08/09/11（4 票）

#### P0-7 应收生成 `totalAmount=0` 时静默跳过（收入性 bug）
- **代码位置**：`MesSalesOutboundServiceImpl.java:119`
- **现状**：`if (totalAmount != null && totalAmount > 0)` 无 else 分支，0 元出库单不生成应收也不告警
- **影响**：赠送/样品出库无应收记录，财务账与业务账对不上
- **修复**：`totalAmount=0` 时打 warn 日志或生成 0 元应收单标记"赠送"
- **识别成员**：04/05/10/12（4 票）

#### P0-8 科目删除只查子科目不查凭证引用（违反财务铁律）
- **代码位置**：`MesAccountSubjectServiceImpl.java:72-78`
- **现状**：`removeById` 只查 `parentId`，不查 voucher/应收/应付引用
- **影响**：已用科目被物理删除，历史凭证/单据成孤儿
- **修复**：删除前校验 `c_mes_voucher`/`c_mes_receivable`/`c_mes_payable` 引用；已用科目只能停用不能删
- **识别成员**：03/04/05/06（4 票）

### 🔴 功能缺失类

#### P0-9 凭证管理菜单开着但后端 404
- **现状**：菜单已注册（`mes_finance_voucher`）、权限已授权、表已建（`c_mes_voucher`），但 `finance/voucher/` 目录存在却 0 文件；前端 `voucher/` 目录不存在
- **影响**：客户点击"凭证管理"404，业财管控模块形象崩塌
- **修复**：**二选一**：① 补凭证管理 CRUD（凭证明细 + 借贷平衡校验）；② 临时从菜单注册表移除，待后续迭代
- **识别成员**：03/06（2 票）

#### P0-10 应收/应付列表无客户/供应商列
- **现状**：前端 `receivable.data.ts`/`payable.data.ts` 无 `customerId`/`supplierId` 字段，列表只显示单号/金额/状态
- **影响**：财务不知道"谁欠钱"，两家客户以上即不可用
- **修复**：列表补客户/供应商列（`@Dict` 表字典翻译）
- **识别成员**：03/09（2 票）

#### P0-11 前端科目表单缺 `parentId` 字段（树形结构 UI 无法使用）
- **现状**：后端 `MesAccountSubject` 有 `parentId`，`subject.data.ts` 的 `formSchema` 无该字段；`SubjectDrawer.vue` 也无
- **影响**：客户无法通过 UI 建立树形科目，所有科目平级
- **修复**：`formSchema` 补 `parentId` 字段（树形选择器 `TreeSelect`）
- **识别成员**：03/09（2 票）

### 🔴 部署/架构类

#### P0-12 SQL 不在 Flyway 扫描路径（客户部署时表建不起来）
- **现状**：`V9.0.0__mes_finance_init.sql` 在 `project-mes/db/`，而 `application-*.yml` 只配 `classpath:flyway/sql/mysql`
- **影响**：客户部署时 5 张财务表 + 4 个字典 + 角色授权不会自动执行，系统直接报错
- **修复**：**二选一**：① 把 SQL 移到 `jeecg-system-start/src/main/resources/flyway/sql/mysql/`；② 修改 Flyway locations 配置，把 `project-mes/db/` 加入扫描路径
- **识别成员**：06（1 票，主控复核属实，升级共识）

#### P0-13 业财联动硬编码 `@Autowired` 直连（架构债务）
- **现状**：`MesSalesOutboundServiceImpl` 直接 `@Autowired IMesReceivableService`，同事务强耦合；应收生成失败会导致出库单审核回滚（死循环）
- **影响**：跨模块边界模糊，未来拆分微服务时需大改
- **修复**：改 Spring `ApplicationEventPublisher` + `@TransactionalEventListener(AFTER_COMMIT)`，应收/应付生成失败只记日志不回滚出库
- **识别成员**：06/07/08（3 票）

#### P0-14 销售出库累计出库量校验无 `FOR UPDATE`（并发超发）
- **现状**：`MesDeliveryNoteServiceImpl` 已有 `selectByIdForUpdate`，但销售出库的累计出库量校验是裸查询
- **影响**：并发审核同一发货单，累计出库量校验失效 → 超发
- **修复**：累计校验前 `SELECT ... FOR UPDATE` 锁发货单行
- **识别成员**：08（1 票，主控复核属实，升级共识）

## 四、P2 建议项（可选优化）

- 金额无千分位格式渲染（前端）
- "树形视图"按钮只刷新列表，未切换树形/平铺
- 删除科目静默复活改语义（`del_flag=0` 恢复已删数据）
- 字典 key 散落（`sourceType` 中文硬编码"销售出库"）
- 库存台账 `bizId` 用业务 code 不用 id（未来 code 变更会断链）
- 出库单 `2(待审核)` 状态无入口
- 无逾期/账龄视角（应收列表无逾期天数列）
- 无手工新增应收/应付入口（期初建账无法完成）
