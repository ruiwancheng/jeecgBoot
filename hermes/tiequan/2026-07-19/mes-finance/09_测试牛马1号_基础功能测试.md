#### TC-SUB-005 新增科目-前端选择父科目
- **测试步骤**：打开新增科目抽屉，尝试选择父科目
- **预期结果**：表单中应有"上级科目"下拉树，可选择已有科目作为 parentId

#### TC-SUB-008 删除科目-逻辑删除后同码再建
- **前置条件**：已删除 code="1001" 的科目（del_flag=1）
- **请求**：POST `/mes/finance/subject/add`，code="1001"
- **预期结果**： resurrect 已删除记录，或新增成功
- **当前代码是否满足**：⚠️ **部分满足**
- **缺陷等级**：**P1**
- **问题描述**：
  - `save()` 第 52-58 行有 `selectDeletedByCode` + `resurrect` 逻辑，可复活已删除记录。
  - 但 DB 唯一索引为 `(code, del_flag)` 联合唯一。若同 code 被删除两次（del_flag=1 出现两次），第二次删除时会违反唯一索引。
  - 由于 MySQL 中 `del_flag` 只有 0/1 两种值，同 code 最多只能有一条 del_flag=0 和一条 del_flag=1，第二次删除（即再建再删）会导致 `(code, 1)` 重复。
- **修复建议**：改用 `id` 作为删除标记的一部分，或使用 `deleted_id` 策略（删除时将 id 拼入 code 或单独记录），或放弃唯一索引改由应用层保证。

#### TC-REC-004 生成链路-客户为空
- **前置条件**：出库单 customerId = null
- **操作**：审核该出库单
- **预期结果**：应抛出明确异常（如"出库单客户不能为空，无法生成应收"）或跳过生成
- **当前代码是否满足**：❌ **不满足**
- **缺陷等级**：**P0**
- **问题描述**：代码直接 `ar.setCustomerId(e.getCustomerId())`，未做非空校验。若 customerId 为 null，插入时 DB 层 `customer_id VARCHAR(32) NOT NULL` 会抛出 `DataIntegrityViolationException`，事务回滚，但错误信息不友好。
- **修复建议**：在 `audit()` 第 4 步前增加 `if (!StringUtils.hasText(e.getCustomerId())) throw new JeecgBootException("出库单客户不能为空，无法生成应收单");`

#### TC-REC-005 生成链路-重复审核防重

- **操作**：再次审核同一出库单

- **当前代码是否满足**：⚠️ **部分满足**
- **缺陷等级**：**P1**
- **问题描述**：
  - 出库单 `auditWithGuard` 原子更新状态，重复审核会返回 0 行，抛出异常，**可以防止重复生成**。
  - 但应收单表本身没有 `source_bill_id` 唯一索引，若并发审核（极端情况）或异常重试，仍可能产生重复应收。
- **修复建议**：在 c_mes_receivable 表增加 `UNIQUE INDEX uk_rec_source_bill (source_bill_id, del_flag)`，或在生成前查询是否已存在。

## 三、缺陷汇总

### P0（阻断性缺陷，必须修复）

| # | 缺陷描述 | 影响范围 | 修复建议 |
|---|----------|----------|----------|
| 1 | **前端科目表单缺失 parentId 字段**，无法建立树形结构 | 会计科目模块核心功能（树形） | 在 `subject.data.ts` formSchema 中增加 parentId 字段，使用 JTreeSelect 组件绑定 `/mes/finance/subject/tree` |
| 2 | **应收生成链路未校验 customerId 非空**，DB NOT NULL 约束会抛不友好异常 | 销售出库审核 → 应收生成 | 在 `MesSalesOutboundServiceImpl.audit()` 生成应收前增加 customerId 非空校验 |
| 3 | **应付生成链路未校验 supplierId 非空**，DB NOT NULL 约束会抛不友好异常 | 采购入库审核 → 应付生成 | 在 `MesPurchaseReceiptServiceImpl.audit()` 生成应付前增加 supplierId 非空校验 |

### P1（严重缺陷，建议尽快修复）

| # | 缺陷描述 | 影响范围 | 修复建议 |
|---|----------|----------|----------|
| 1 | **科目表唯一索引 (code, del_flag) 存在逻辑删除冲突**，同 code 最多只能删除一次 | 会计科目删除/重建 | 改用应用层唯一性保证，或调整索引策略（如删除时将 id 拼入 code） |
| 2 | **应付单金额固定为 0**，未实现自动计算 | 应付账款业务价值 | 待采购价格模块完成后，从入库单明细计算合计金额 |
| 3 | **应收/应付表缺少 source_bill_id 唯一索引**，极端并发下可能重复生成 | 业财联动数据一致性 | 增加 `UNIQUE INDEX (source_bill_id, del_flag)` |
| 4 | **应收/应付重复生成无应用层兜底**，仅依赖来源单据状态守卫 | 业财联动数据一致性 | 生成前查询是否已存在对应 source_bill_id 的未删除单据 |
