## 一、被审计模块概述

本次审计覆盖 MES 财务模块 Phase2 新增的三个子模块：

| 子模块 | 后端代码 | 前端代码 | 核心功能 |
|:---|:---|:---|:---|
| **凭证管理** | `MesVoucherController` / `MesVoucherServiceImpl` / `MesVoucher` / `MesVoucherItem` | `voucher/index.vue` / `VoucherDrawer.vue` / `voucher.data.ts` / `voucher.api.ts` | 手工录入凭证、多行明细、借贷平衡校验、草稿/审核状态流转 |
| **收款管理** | `MesCollectionController` / `MesCollectionServiceImpl` / `MesCollection` | `collection/index.vue` / `collection.data.ts` / `collection.api.ts` | 收款单登记、关联应收单、自动更新应收已收金额/状态 |
| **付款管理** | `MesPaymentController` / `MesPaymentServiceImpl` / `MesPayment` | `payment/index.vue` / `payment.data.ts` / `payment.api.ts` | 付款单登记、关联应付单、自动更新应付已付金额/状态 |

**联动关系**：收款单/付款单保存时，会实时更新关联应收单/应付单的 `receivedAmount`/`paidAmount`、`unsettledAmount` 和 `status`（1→2→3）。凭证模块为完全独立的手工录入，与收付款无自动关联。

## 二、风险点清单（按文件）

### P0 — 阻断性风险（必须修复）

| # | 文件 | 风险点 | 业务影响 | 修复建议 |
|:---:|:---|:---|:---|:---|
| P0-1 | `collection/index.vue` / `payment/index.vue` | **新增收款/付款跳转路由不存在** | `handleAdd()` 跳转 `/project/mes/finance/collection/add` 和 `/project/mes/finance/payment/add`，但前端无对应页面文件，客户点击"新增收款/付款"直接 404 | **二选一**：① 补建 `CollectionAdd.vue` / `PaymentAdd.vue` 表单页；② 改为当前页弹窗（Drawer/Modal）模式，与凭证管理保持一致 |
| P0-2 | `collection/index.vue` / `collection.data.ts` / `collection.api.ts` | **收款单无编辑/删除/作废入口** | 列表页只有"新增"和"导出"按钮，无行操作；`collection.api.ts` 无 `editCollection`/`deleteCollection` API。客户录错收款单后无法修正，只能找 IT 改库 | 补 `edit`/`delete`/`cancel` 接口和前端操作列；状态机补 `0已作废`；作废时回滚应收单金额和状态 |
| P0-3 | `payment/index.vue` / `payment.data.ts` / `payment.api.ts` | **付款单无编辑/删除/作废入口** | 同 P0-2，付款单录错无法修正 | 同 P0-2 |
| P0-4 | `voucher/VoucherDrawer.vue` | **凭证保存后无响应处理** | `handleSubmit()` 调用 `saveOrUpdateVoucher` 后无 `try/catch`，后端报错（如凭证号重复、借贷不平衡）时前端无提示，客户以为保存成功 | 补 `try/catch` 和 `message.error()`；后端校验失败时明确提示原因 |
| P0-5 | `MesCollectionServiceImpl` / `MesPaymentServiceImpl` | **收款/付款并发更新应收/应付无锁** | 两个并发收款请求同时读取 `unsettledAmount`，各自校验通过后都更新，导致 `receivedAmount` 被覆盖或超收 | 更新应收/应付单前加 `SELECT ... FOR UPDATE` 行锁，或改用 `UPDATE ... SET received_amount = received_amount + ?` 原子更新 |
| P0-6 | `MesCollectionServiceImpl` / `MesPaymentServiceImpl` | **部分收款状态判断逻辑错误** | `newReceived.compareTo(BigDecimal.ZERO) > 0 && newReceived.compareTo(ar.getAmount()) < 0` 时设状态为 `2`，但当 `newReceived == 0` 时状态被设为 `3`（已结清）。虽然前端金额>0，但逻辑漏洞明显 | 改为：`newReceived.compareTo(ar.getAmount()) >= 0 ? "3" : (newReceived.compareTo(BigDecimal.ZERO) > 0 ? "2" : "1")` |
| P0-7 | `VoucherDrawer.vue` / `MesVoucherServiceImpl` | **凭证 vs 收付款关系完全断裂** | 凭证是手工独立录入，收款/付款不自动生成凭证；`sourceType` 字典虽有 `mes_voucher_source`，但无联动逻辑。客户无法理解"收款后要不要手工做凭证" | **二选一**：① 收款/付款审核后自动生成凭证（推荐）；② 在收款/付款单详情页增加"生成凭证"按钮，手工触发 |

### P1 — 高优风险（建议本迭代修复）

| # | 文件 | 风险点 | 业务影响 | 修复建议 |
|:---:|:---|:---|:---|:---|
| P1-1 | `VoucherDrawer.vue` | **借贷平衡校验体验差** | 底部仅显示 `借方合计: xxx | 贷方合计: xxx 不平衡!`，无差额提示；且 `drTotal`/`crTotal` 用 `toFixed(2)` 返回字符串比较，`"100.00" !== "100"` 会导致误判 | ① 显示差额 `差额: xxx`；② 改用数值比较而非字符串比较；③ 不平衡时禁用保存按钮 |
| P1-2 | `VoucherDrawer.vue` | **科目选择无搜索/无级联** | 每行科目用 `JSearchSelect` 但仅绑 `dict="c_mes_account_subject,name,id"`，无树形/无拼音搜索；科目多时客户找科目困难 | 改用 `JTreeSelect` 支持树形科目；或加拼音搜索；常用科目置顶 |
| P1-3 | `collection.data.ts` / `payment.data.ts` | **收款/付款列表无关联单号列** | 列表只显示收款单号/客户/金额/日期，不显示关联的应收单号/应付单号；客户无法追溯"这笔钱是收哪张单的" | 列表补 `receivableId`/`payableId` 列（字典翻译为应收/应付单号） |
| P1-4 | `MesCollectionServiceImpl` / `MesPaymentServiceImpl` | **超额收款仅抛异常，无前端前置提示** | 后端校验 `amount > unsettled` 抛异常，但前端无实时提示；客户填完表单点保存才报错，体验差 | 前端选择应收单后实时显示 `未结金额`，输入金额超过时即时标红提示 |
| P1-5 | `voucher.data.ts` | **凭证号无自动生成规则** | 客户需手工输入凭证号，易重复；无按日期+流水号自动生成 | 补自动生成规则（如 `PZ-yyyyMMdd-001`），允许客户修改 |

## 三、关键业务场景验证

### 场景 1：财务人员录入一张收款单（部分收款）

**客户操作路径**：
1. 进入"收款管理" → 点击"新增收款" → **404 错误** ❌
2. （假设页面存在）选择客户 → 选择关联应收单 → 输入收款金额 → 保存

**当前阻断点**：P0-1 路由不存在，流程无法开始。

**假设修复后的问题**：
- 选择应收单后无"未结金额"显示，客户不知道还能收多少（P1-4）
- 输入超过未结金额时，保存才报错（P1-4）
- 保存成功后，需手动切到"应收账款"模块才能看到状态从"未结清"变为"部分结清"（P1-7）
- 不会自动生成凭证，客户需手工到"凭证管理"再录一张收款凭证（P0-7）

### 场景 2：财务人员录入一张付款单（全额付款）

同场景 1，问题完全一致。

### 场景 3：财务人员手工录入一张凭证

**客户操作路径**：
1. 进入"凭证管理" → 点击"新增凭证" → 填写凭证号/日期/摘要 → 添加明细行 → 选科目/输金额 → 保存

**当前问题**：
- 凭证号需手工输入，无自动生成（P1-5）
- 科目选择无树形、无搜索，科目多时难找（P1-2）
- 借贷不平衡时仅底部红字提示，无差额显示（P1-1）
- 保存后若后端报错（如凭证号重复），前端无提示（P0-4）
- 审核后发现错误，无法反审核或红冲（P1-6）

## 六、总结

**一句话结论**：凭证/收款/付款三个模块的后端骨架已搭好，但**前端收款/付款入口 404、凭证与收付款完全断裂、无编辑/删除/作废/红冲**，当前状态无法交付真实客户使用。

**客户最痛的 3 个点**：
1. **点"新增收款"404** — 功能完全不可用
2. **收款后不知道应收单状态变了没有** — 需手动跨模块查看
3. **收款后还要手工做凭证** — 财务工作量翻倍，且易漏做

**综合评分：4 / 10** — 骨架及格，体验不及格，建议完成第一批次修复后再交付。
