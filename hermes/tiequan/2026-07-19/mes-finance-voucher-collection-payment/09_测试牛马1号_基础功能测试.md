## 八、缺陷汇总（按优先级）

| 优先级 | 缺陷 | 影响 |
|--------|------|------|
| **P0** | 收款/付款前端新增页面缺失，点击“新增收款/新增付款”跳转 404 | 用户无法录入收付款单 |
| **P0** | 收款/付款无编辑/删除/作废接口与前端操作 | 收付款单只能新增，无法修正错误，业务无法闭环 |
| **P1** | 收款/付款权限码未在 SQL `sys_permission` 中注册 | 可能出现按钮/接口 403 |
| **P1** | 收款/付款单号唯一性无 Service 层友好校验 | 数据库直接抛唯一索引异常，用户体验差 |
| **P1** | 收款/付款删除/作废时未回滚应收/应付已收已付金额 | 导致应收应付数据不一致 |
| **P2** | 收款/付款状态使用 `yn` 字典，与业务语义不符 | 显示“是/否”而非“已收款/已作废” |
| **P2** | 三个模块均未提供 Excel 导入功能 | 若需求包含导入则未满足 |

## 九、建议修复顺序

1. **P0**：补齐收款/付款前端新增页面（或改为抽屉表单），并确保路由可访问。  
2. **P0**：为收款/付款增加编辑、删除/作废接口，删除/作废时回滚应收/应付金额。  
3. **P1**：在 SQL 或启动初始化中显式注册 `mes:collection:*` / `mes:payment:*` 到 `sys_permission`，并为角色授权。  
4. **P1**：Service 层增加 `code` 唯一性校验，返回友好提示。  
5. **P2**：为收付款状态建立专用字典（如 `mes_collection_status` / `mes_payment_status`）。  
6. **P2**：评估是否需要 Excel 导入，若需要则补充 `/importExcel` 与权限。
