# 05_产品大佬3号_资损合规视角

> 审计对象：MES 盘点单 V2
> 审计日期：2026-07-29

## P0-1 validateBookQty 金额保护 🔴 P0（FOR UPDATE 但无金额校验）

```java
org.jeecg.modules.mes.basic.entity.MesInventory inv = inventoryMapper.selectForUpdate(item.getMaterialId(), warehouseId);
BigDecimal cur = inv != null && inv.getCurrentQty() != null ? inv.getCurrentQty() : BigDecimal.ZERO;
if (item.getBookQty() == null || item.getBookQty().compareTo(cur) != 0) { throw ... }
```

**漏洞：** 校验了 `bookQty` 数量一致性，但**没有校验 `unitCost`**！调用方可以传任意 `unitCost`。

**攻击：** 抽盘行 `{ materialId: 'M1', bookQty: 100, actualQty: 110, unitCost: 9999 }` → `diff=10, diffAmount=10×9999=99990` → 盘盈入库 99990 金额 → 库存金额被放大 → 成本扭曲。

**现状防御：** 调用方通过 `onMaterialChange` 预填 `movingAvgCost`——但这只是前端防线（API 可绕过）。🔴 P0

修复：`validateBookQty` 同时校验 `unitCost` 等于当前物料的 `moving_avg_cost`。

## refreshItems 中的金额覆盖 🔴 P0（同边界2号）

刷新：`snapshotItems` 重新从 DB 读 `unitCost`（新快照成本）→ 旧行 `unitCost` 被替换。如果用户用手工成本（而非系统移动平均）→ 刷新后**手工成本丢失**。🔴 P0（金额数据丢失）

## 金额链一致性 ✅
- 审核时 qty 来自最新明细（`queryWithItems` within lock）✅
- 入库单 amount=盘点 diffQty×盘点 unitCost（同一事务）✅
- 库存增减量 = 出入库单审核（Spring 代理调用，全原子）✅

## 零库存盘盈成本后果 🔴 P1
见边界2号：`unitCost=0` → `updateMovingAvgCostOnStockIn` 条件不满足 → 跳过成本更新 → `c_mes_material.moving_avg_cost` 未变 → 台账户 `inAmount=0`。业财口径偏差可积累。

## 结论
2 P0（validateBookQty 缺金额校验、refreshItems 覆盖手工成本）、1 P1（零库存盘盈成本）。金额校验空窗是最大风险。

**风险汇总：2 P0 / 1 P1 / 0 P2**
