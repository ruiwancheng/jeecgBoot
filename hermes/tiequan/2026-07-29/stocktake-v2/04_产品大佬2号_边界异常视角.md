# 04_产品大佬2号_边界异常视角审计

> 审计对象：MES 盘点单 V2
> 审计日期：2026-07-29

## refreshItems 分析 🔴 P0（覆盖已填实盘数）

```java
// refreshItems():
items = snapshotItems(exist.getWarehouseId());  // book + actual 都设=book
itemMapper.delete(delQw);                        // 删全部旧行
calcAndSaveItems(exist, items);                  // 全量重插
```

**关键问题：** `snapshotItems` 将 `actualQty` 设为 `bookQty`（账面=实盘，差异=0）。如果用户已填了 30 个物料的实盘数，刷新后**全部丢失**。

前端虽显示成功 msg，但用户期望"刷新账面数（只更新 book_qty）"，而非"重设全部金额"。**这是 bug 不是 feature。**

修复：`refreshItems` 应保留已有 `actualQty`（按 materialId 匹配旧行），只更新 `bookQty` + `unitCost` + 新增物料行+删已灭失物料行。

## P0-1 校验 validateBookQty 分析 🟡 P2

```java
// 抽盘新行: FOR UPDATE 锁库存行 + 校验 book_qty == current_qty
// 编辑原有行: 校验 book_qty == 原快照
```

**时序 race：** 批量添加物料逐物料拉账面（无锁），提交时后端 FOR UPDATE 逐行校验：
1. 前端拉取 M1 账面=10（普通 SELECT 无锁）
2. 后端校验时 FOR UPDATE 锁→发现被改为 8 → 抛异常
3. 用户看到"账面数量与当前库存不一致"错误

**评估：** 比 V1 有进步（V1 信任客户端 book_qty）。此异常**正确且期望的**——用户被通知库存变化了。🟡 P2（用户体验可优化："库存已从 10 变为 8，是否按 8 继续？"但 V1 可接受）

## 快照 qty>0 + 抽盘 book=0 组合 🔴 P1

**零库存盘盈流程：**
1. 快照 `qty>0` → 物料 M 不在明细中（账面=0）
2. 用户抽盘添加行 → `addLine()` 设 `bookQty=0`
3. `validateBookQty` 用 FOR UPDATE 读库存→ `cur=0` → 校验 `0==0` 通过 ✅
4. 审核：`actualQty=5, bookQty=0` → `diff=5` → 盘盈 → 生成入库单 `qty=5, unitCost=0`
5. `updateMovingAvgCostOnStockIn(materialId, 5, 0, ...)` → `unitCost > 0` 条件不满足 → **跳过成本更新**

**后果：** 库存增加 5 但成本表未更新 → 库存数量**不等于**库存金额×单位成本 → 业财隔离。如果这是计划内（0 成本盘盈），则应该明确告知用户。🟡 P2（设计决策）。

## 批量审核事务一致性 🔴 P0

```js
// index.vue batchAudit():
for (const r of selectedRows) { await auditStocktake({ id: r.id }); }
```

**问题：** 选 3 条→逐条审核→前 2 条成功、第 3 条失败→前 2 条已审计不可回滚（无反审核）。

虽然每条审核内部是原子事务，但跨单据**非事务性**。更严重的是：第 3 条抛异常→`message` 被吞→前 2 条静默成功。🔴 P0

## 结论
2 P0（refreshItems 覆盖实盘数、批量审核非事务性）、1 P1（零库存盘盈成本跳过）、2 P2。
