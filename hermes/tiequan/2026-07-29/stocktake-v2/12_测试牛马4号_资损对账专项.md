## 金额一致性 🔴 P0

V2 新增 validateBookQty 校验了数量，**但未校验 unitCost**。攻击者可通过 API 提交任意 unitCost→差异金额被放大→成本污染。验证: 盘点审核时入库单 `item.getUnitCost()` 来自盘点明细→如果不做服务端校验，用户/攻击者可改单价→影响库存成本。🔴 P0

## 零库存盘盈成本 🔴 P1

`bookQty=0, actualQty=5, unitCost=0` → `diff=5, diffAmount=0` → 入库 `qty=5, unitCost=0` → `updateMovingAvgCostOnStockIn` 跳过 → `moving_avg_cost` 不变。库存量增加了但金额未变→avg 被稀释。如果计划的：应告知用户。🔴 P1

## refreshItems 中的 snapshotTime 更新 🔴 P0

```java
// L285: updateById 更新 snapshotTime
baseMapper.updateById(new MesStocktake().setId(id).setSnapshotTime(exist.getSnapshotTime()));
```
与 V1 同样的模式（`updateById` 空 entity）。MyBatis-Plus `NOT_NULL` 字段策略下只更新 `snapshotTime`，忽略其他 null 字段 ✅。但实现方式不清晰—建议用 `@Update` 注解的单字段更新。
