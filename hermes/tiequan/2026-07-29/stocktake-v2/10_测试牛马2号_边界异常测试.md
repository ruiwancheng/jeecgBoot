## 已删除物料边界
```js
// materialMap 无 → dictText 无 → fallback record.materialId (裸ID)
```
如果物料被物理删除（非软删除）→ `materialId_dictText` 为 null（`c_mes_material` 行已不存在）→ 最终显示裸 ID。✅ 不会崩溃但 UX 差。

## E2E 自身的脆弱性
`stocktake.spec.ts` 的脆弱点：
- **依赖后端在线**（所有 fixture 通过 API 建仓/料/入库）— 后端离线 = E2E 全挂
- **依赖 `MAT-STE-` 前缀不被冲突** — `Date.now()` 只取后 8 位→每 100 秒冲突一次
- **`expect(bodyText).toContain(fx.matCode)`** — 全文搜索误判风险
- **`dbCleanup` 函数签名未定义** — `import { dbCleanup }` 但测试文件未显示此 helper 的位置

## 结论
V2 安全加固明显（validateBookQty 数量校验、generatedIn/OutId 清空）。1 P0（unitCost 无校验）、0 P1、2 P2（E2E 脆弱性）。
