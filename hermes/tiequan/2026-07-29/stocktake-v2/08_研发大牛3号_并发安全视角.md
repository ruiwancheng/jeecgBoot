# 08_研发大牛3号_并发安全视角

> 审计对象：MES 盘点单 V2
> 审计日期：2026-07-29

## refreshItems 并发 🔴 P1

```
T1: refreshItems(id)  → FOR UPDATE → 删旧行 → 重插新行 → 释放锁
T2: updateWithItems(id) → FOR UPDATE → 等待 T1 释放 → 读 status='1' ✅
```

FOR UPDATE 互斥保障 ✅

**但 T1 和 T3（用户正在 Drawer 中编辑）的时序：**
1. 用户打开 Drawer（读 items）
2. 用户修改 actual_qty=120
3. 用户点"刷新账面数"→刷新全量 weight 覆盖（actual_qty 丢失）
4. 用户保存→actual_qty=账面（非 120）

前端应在"刷新"前警告，但后端无法防止。🟡 P2（UX 层级）。

## 批量添加物料 + validateBookQty race 🔴 P1

```
T1（前端）: onBatchMaterials → 逐物料 API 拉账面 → bookQty₍M₁₎=10, bookQty₍M₂₎=5
T2（后端）: 库存变动 → M1 qty=8
T3（提交）: validateBookQty → M1 book=10 ≠ cur=8 → 抛异常
```

抛异常是正确行为（保护数据一致性）✅。但用户看到"账面数量与当前库存不一致"→"什么？我没改库存啊？"→ 困惑。🟡 P2（缺少上下文提示）。

## refreshItems ↔ 审核并发
```
T1: refreshItems → FOR UPDATE
T2: audit → FOR UPDATE 等待 T1 → 读 status='1' → CAS 成功
```
互斥 ✅
