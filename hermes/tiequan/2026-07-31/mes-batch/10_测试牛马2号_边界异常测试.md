# 10_测试牛马2号_边界异常测试 — MES 批次管理审计

**审计角色**: 测试牛马2号 — 边界异常测试  
**审计日期**: 2026-07-31  

## 审计发现

### P0-2 Mapper 方法无 SQL 实现（P0）
- **文件**: `MesBatchLedgerMapper.java:14,19`
- **描述**: `selectByBiz` 被 Service 调用但无 SQL 实现 → 运行时 BindingException
- **修复建议**: 加 `@Select` 注解

### P1-3 createBatch materialId=null → NPE（P1）
- **文件**: `MesBatchServiceImpl.java:31`
- **描述**: 当 Controller 收到 `materialId: null` 的请求时，`materialId.substring(...)` 直接 NPE
- **修复建议**: 方法开头校验非空

### P1-7 stockOutFifo qty=0 不会终止循环（P1）
- **文件**: `MesBatchInventoryServiceImpl.java:62`
- **描述**: `remaining = qty`，当 `qty` 为 `BigDecimal.ZERO` 时 `remaining.compareTo(BigDecimal.ZERO) > 0` 为 false → 循环不执行，返回空 outDetails → 调用方（销售出库）认为已经处理完毕 → 实际上什么都没扣。如果 `qty` 为负数同理但 compareTo <= 0 break 导致直接返回
- **修复建议**: 方法开头 `if (qty == null || qty.compareTo(BigDecimal.ZERO) <= 0) throw new JeecgBootException("出库数量必须大于0")`

### P1-8 batch_enabled=NULL 时降级崩溃（P1）
- **文件**: `MesPurchaseReceiptServiceImpl.java:180`; `MesSalesOutboundServiceImpl.java:131`; `ProductionPickingServiceImpl.java:131`; `CompletionReceiptServiceImpl.java:136`
- **描述**: `mat.getBatchEnabled()` 返回 `Integer`，当值为 NULL（DDL `DEFAULT 0` 但可能历史数据为 NULL）时 `Integer.valueOf(1).equals(null)` 返回 `false` — 不会崩溃但也不会创建批次。好消息是这不影响主流程。但如果有人后续 `mat.getBatchEnabled() == 1` 比较 → 拆箱 NPE
- **修复建议**: `Integer.valueOf(1).equals(mat.getBatchEnabled())` — 这写法本身安全（Integer.equals 接受 null），不需要改但建议统一 `BatchEnabled` 默认值

### P2-9 stockIn qty 为负数的入库（P2）
- **文件**: `MesBatchInventoryServiceImpl.java:27`
- **描述**: `stockIn` 不校验 qty 符号。负数入库 = 变相出库，但 `inv.getQty().add(qty)` 对负数的处理不是"减少库存"而是"增加一个负数"（实际效果是减少），语义模糊
- **修复建议**: 校验 `qty.compareTo(BigDecimal.ZERO) > 0`

### P3-5 前端 traceability.data.ts 复用 ledgers 的字段定义混淆（P3）
- **文件**: `traceability.data.ts:5-15`
- **描述**: 追溯页面 columns 包含 `bizType/bizNo/inQty/outQty/unitCost` 等流水字段，但 `index.vue` 用的是 `queryBatchList`（查主档）作为 list 接口。主档响应没有 inQty/outQty 字段 → 列显示为空
- **修复建议**: 追溯页列表应调 `queryLedgerList` 而非 `queryBatchList`，或 columns 改为批次主档的字段
