# 08_研发大牛3号_并发安全视角 — MES 批次管理审计

**审计角色**: 研发大牛3号 — 并发安全视角  
**审计日期**: 2026-07-31  

## 审计发现

### P0-1 批次号取号无锁（P0）
- **文件**: `MesBatchServiceImpl.java:33-36`
- **描述**: 取号 count+1 无任何并发保护。并发场景：两个线程同时 count 得 10 → 都设 seq=11 → 两个 id 不同的批次共用同一个 batchNo → 第二个 `this.save(batch)` 触发 `uk_batch_no_del` 唯一索引冲突
- **修复建议**: `@Select("SELECT batch_no FROM c_mes_batch WHERE batch_no LIKE CONCAT(#{prefix},'%') ORDER BY batch_no DESC LIMIT 1 FOR UPDATE") String selectLatestBatchNo(@Param("prefix") String prefix)`

### P0-3 生产领料先扣再改状态（P0）
- **文件**: `ProductionPickingServiceImpl.java:127-141`
- **描述**: 库存扣减在 `auditWithGuard` 之前。并发：线程A和B同时审核同一领料单 id=PK01。A 先扣库存（stockOut + stockOutFifo），然后 `auditWithGuard` 成功 → A 返回。B 也扣库存（再次多扣），然后 `auditWithGuard` WHERE status='1' 失败 → B 抛异常。但 B 的事务回滚只回滚 B 的扣减 → 库存已多扣（A 扣的+ B 的还没回滚？B 在同一事务内回滚所以不会多扣，但主库存 stockOut 在扣减前没有 FOR UPDATE → 可能丢失更新）
- **修复建议**: 先 `auditWithGuard`，成功后再扣库存。与销售出库 audit 对齐

### P0-5 stockOutFifo 返回值被丢弃（P0）
- **文件**: `MesSalesOutboundServiceImpl.java:133`; `ProductionPickingServiceImpl.java:132`
- **描述**: FIFO 出库返回的批次成本被忽略 → 销货成本数据丢失
- **修复建议**: 接收返回值并写入明细

### P1-4 冻结批次仍可被出库（P1）
- **文件**: `MesBatchInventoryServiceImpl.java:60`
- **描述**: `selectFifoByMaterialForUpdate` 只查 `c_mes_batch_inventory`（条件：material_id + warehouse_id + qty>0 + del_flag=0），不 JOIN `c_mes_batch` 检查 status。冻结的批次 qty > 0 → 仍被锁出库 → "冻结"只有主档层面语义，库存层面无守卫
- **修复建议**: SQL 加 `JOIN c_mes_batch b ON b.id = i.batch_id AND b.status IN ('1','4')`

### P1-5 同一单据重复审核无幂等保护（P1）
- **文件**: `MesBatchInventoryServiceImpl.java:27-51, 55-80`
- **描述**: stockIn/stockOutFifo 都不检查 `bizId` 是否已存在。如果调用方（采购入库、销售出库等）的 audit 被重复调用 → 批次库存重复累加/扣减 → 流水重复
- **修复建议**: stockIn/stockOutFifo 内部先检查 `SELECT COUNT(*) FROM c_mes_batch_ledger WHERE biz_type=? AND biz_id=?`，已有记录则跳过

### P2-7 stockIn 新建行并发唯一索引冲突无友好提示（P2）
- **文件**: `MesBatchInventoryServiceImpl.java:35-44`
- **描述**: stockIn 中 `selectForUpdate` 未命中 → 新建 inventory 行 → 并发时 `uk_batch_warehouse` 唯一索引冲突 → `DuplicateKeyException` 抛出 500
- **修复建议**: catch `DuplicateKeyException` → 重试 selectForUpdate
