# 04_产品大佬2号_边界异常视角 — MES 批次管理审计

**审计角色**: 产品大佬2号 — 边界异常视角  
**审计日期**: 2026-07-31  

## 审计发现

### P0-1 批次号并发取号无锁（P0）
- **文件**: `MesBatchServiceImpl.java:33-36`
- **描述**: `this.count(seqQw) + 1` 没有 `FOR UPDATE` 或 `synchronized`。并发请求 count 返回相同值 → 相同 batchNo → `DuplicateKeyException` → 500
- **修复建议**: Mapper 层加 `selectMaxBatchNoForUpdate(@Param("prefix") String prefix)` 用 `SELECT batch_no FROM c_mes_batch WHERE batch_no LIKE CONCAT(#{prefix},'%') ORDER BY batch_no DESC LIMIT 1 FOR UPDATE`

### P0-2 Mapper 方法无 SQL 实现（P0）
- **文件**: `MesBatchLedgerMapper.java:14,19`
- **描述**: `selectByBatchId` 和 `selectByBiz` 声明在 Mapper 接口中，但无 `@Select` 注解也无 XML 映射文件 → MyBatis 启动抛 `BindingException: Invalid bound statement (not found)`
- **修复建议**: 加上 `@Select("SELECT * FROM c_mes_batch_ledger WHERE ...")` 注解，或在 XML 中添加对应 `<select>` 标签

### P1-2 主库存与批次库存不一致（P1）
- **文件**: 跨 `MesInventoryServiceImpl` 和 `MesBatchInventoryServiceImpl`
- **描述**: 主库存（c_mes_inventory）和批次库存（c_mes_batch_inventory）分别独立操作，无数据一致性校验。采购入库先 `inventoryService.stockIn`（主库存）再 `batchService.createBatch` + `batchInventoryService.stockIn`（批次库存）。如果主库存成功但批次库存失败 → 数据不一致
- **修复建议**: 先操作批次库存（因为批次库存依赖主库存的数据），或加最终一致性校验

### P1-3 createBatch materialId=null NPE（P1）
- **文件**: `MesBatchServiceImpl.java:31`
- **描述**: `materialId.substring(0, Math.min(6, materialId.length()))` — 当 `materialId` 为 `null` 时直接 `NullPointerException`。Controller 未做参数校验
- **修复建议**: 方法开头加 `if (!StringUtils.hasText(materialId)) throw new JeecgBootException("物料不能为空")`

### P2-2 qty=0 可创建批次（P2）
- **文件**: `MesBatchServiceImpl.java:28`
- **描述**: `createBatch` 未校验 `qty` 是否大于 0，允许创建数量为 0 的批次。`qty` 为 `null` 或 `BigDecimal.ZERO` 也可能导致问题
- **修复建议**: 加 `if (qty == null || qty.compareTo(BigDecimal.ZERO) <= 0) throw new JeecgBootException("数量必须大于0")`

### P3-2 有效期 > 生产日期未校验（P3）
- **文件**: `MesBatch.java:54-59`, `master.data.ts:61-62`
- **描述**: 前端 DatePicker 未设 `productionDate < expiryDate` 的校验，后端也未校验。用户可能误填反转的日期
- **修复建议**: 前端加自定义 validator，后端 Service 加日期比较
