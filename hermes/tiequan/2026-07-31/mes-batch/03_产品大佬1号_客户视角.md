# 03_产品大佬1号_客户视角 — MES 批次管理审计

**审计角色**: 产品大佬1号 — 客户真实视角  
**审计日期**: 2026-07-31  

## 审计发现

### P0-1 批次号并发取号无锁（P0）
- **文件**: `MesBatchServiceImpl.java:35`
- **描述**: `createBatch` 中取号逻辑 `long seq = this.count(seqQw) + 1` 无任何锁保护。两个请求同时 count 到相同值 → 同一批次号 → `uk_batch_no_del` 唯一索引冲突 → `DuplicateKeyException` → 接口 500
- **修复建议**: 用 `SELECT ... FOR UPDATE` 行锁取最大批次号，或在 catch `DuplicateKeyException` 后重试

### P0-3 生产领料先扣库存再改状态（P0）
- **文件**: `ProductionPickingServiceImpl.java:127-141`
- **描述**: audit 方法先 `inventoryService.stockOut` + `batchInventoryService.stockOutFifo` 扣库存，然后才 `auditWithGuard` 改状态。如果和他人同时审核同一领料单，`auditWithGuard` 返回 0（已被他人审核），但库存已经扣了 → 库存幻扣
- **修复建议**: 调换顺序：先 `auditWithGuard`，成功后再扣库存

### P1-1 批次单位成本后续入库不更新（P1）
- **文件**: `MesBatchInventoryServiceImpl.java:40-46`
- **描述**: stockIn 新建库存行时 `inv.setUnitCost(batch.getUnitCost())`，但已有行直接跳过 → 同一批次多次入库，unitCost 永远是第一次的值
- **修复建议**: 已有行也更新 unitCost（移动平均成本应每次入库后重算）

### P1-4 stockOutFifo 未检查批次冻结（P1）
- **文件**: `MesBatchInventoryServiceImpl.java:59-80`
- **描述**: FIFO 查询 `WHERE qty>0` 不排除冻结状态（status=2）的批次 → 冻结批次仍可出库 → "冻结"功能形同虚设
- **修复建议**: FIFO 查询 JOIN c_mes_batch 并加条件 `AND b.status IN ('1','4')`（仅在用+过期可出库）

### P2-1 批次状态无自动流转（P2）
- **文件**: 全局
- **描述**: batch status=1(在用) 创建后，stockOutFifo 消耗完库存不自动置为 3(已耗尽)，到期不自动置为 4(过期)。需要手动操作或定时任务
- **修复建议**: stockOutFifo 末尾判断 qty=0 → 自动 setStatus("3")；定时任务扫 expiry_date < now → setStatus("4")

### P3-1 新增批次后前端无法显示 batchNo（P3）
- **文件**: `BatchMasterDrawer.vue`, `master.data.ts:34-42`
- **描述**: batchNo 字段设为 disabled，新增保存后需要刷新列表才能看到新批次号
- **修复建议**: 新增成功后在前端显示 batchNo（通过 message 或 alert）
