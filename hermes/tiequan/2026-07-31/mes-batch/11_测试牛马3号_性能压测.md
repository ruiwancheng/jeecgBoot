# 11_测试牛马3号_性能压测 — MES 批次管理审计

**审计角色**: 测试牛马3号 — 性能压测  
**审计日期**: 2026-07-31  

## 审计发现

### P1-2 stockOutFifo FOR UPDATE 高并发串行化（P1）
- **文件**: `MesBatchInventoryMapper.java:34-37`
- **描述**: `selectFifoByMaterialForUpdate` 锁住同物料同仓库的所有 qty>0 行。如果某常用物料有 50+ 批次行，每次出库锁 50 行。高并发（10+ TPS）时，所有出库请求排队等待行锁 → 事务平均等待时间 = (持有锁时间 + 排队)× 并发数
- **修复建议**: 
  1. 参考编码规则模块的 `FOR UPDATE SKIP LOCKED` 模式
  2. 或分两阶段：先 SELECT 无锁确定扣哪些行 → 再 `FOR UPDATE` 锁单行逐行扣

### P1-9 出库事务持有锁时间长（P1）
- **文件**: `MesSalesOutboundServiceImpl.java:115-138`
- **描述**: audit 事务包含：auditWithGuard → stockOut(主库存) → stockOutFifo(批次库存+FOR UPDATE) → 检查发货单状态 → 生成应收 → 检查订单状态。事务持有期间库存行一直被锁，其他出库操作等待
- **修复建议**: stockOutFifo 放在事务末尾，或者将非库存操作（应收生成、状态回写）移到事务外（使用后置处理或补偿机制）

### P2-5 createBatch count 全表扫描（P2）
- **文件**: `MesBatchServiceImpl.java:34`
- **描述**: `this.count(seqQw)` → `SELECT COUNT(*) FROM c_mes_batch WHERE batch_no LIKE 'BT-ABC-20260731%'` — 即使有 `uk_batch_no_del` 索引，LIKE 左前缀匹配可利用索引，合理
- **修复建议**: 不紧急，随行锁修复一起解决

### P2-10 流水表无限增长（P2）
- **文件**: `V8.0.0__mes_batch_init.sql:53-74`
- **描述**: 每次出入库写一条流水（c_mes_batch_ledger），日积月累表膨胀。没有分区策略、没有归档机制
- **修复建议**: MVP 阶段暂不处理，Phase 2 考虑按月分区或定期归档

### P3-6 stockOutFifo 循环内逐行 updateById（P3）
- **文件**: `MesBatchInventoryServiceImpl.java:70`
- **描述**: FIFO 扣减中每行单独 `this.updateById(inv)`，如果一次出库跨 5 个批次 → 5 次 UPDATE。不如收集变更行后批量 UPDATE
- **修复建议**: 改用 `updateBatchById(invs)` 批量更新
