**审计角色**: 研发大牛2号 — 代码细节视角

## 审计发现

### P0-1 批次号取号无锁（P0）
- **文件**: `MesBatchServiceImpl.java:33-36`
- **描述**: `long seq = this.count(seqQw) + 1` — 经典并发漏洞。MyBatis-Plus count 执行的是 `SELECT COUNT(*) FROM c_mes_batch WHERE batch_no LIKE 'prefix%'` 无锁
- **修复建议**: 见总报告修复方案

### P1-3 createBatch materialId=null → NPE（P1）
- **文件**: `MesBatchServiceImpl.java:31`
- **描述**: `materialId.substring(0, Math.min(6, materialId.length()))` — 当 materialId=null 直接 NullPointerException。Controller 的 add 方法未校验 materialId 非空
- **修复建议**: 开头加 `Assert.hasText(materialId, "物料不能为空")`，或 `Objects.requireNonNull(materialId)`

### P1-4 unfreeze 无状态检查（P1）
- **文件**: `MesBatchServiceImpl.java:69-75`
- **描述**: `unfreeze` 方法不检查当前状态直接 `setStatus("1")`。已耗尽(3)/过期(4) 的批次也可以被解冻
- **修复建议**: 与 freeze 对称：`if ("3".equals(b.getStatus())) throw new JeecgBootException("已耗尽的批次不能解冻")`；同理加过期检查

### P1-5 stockIn 数量未校验（P1）
- **文件**: `MesBatchInventoryServiceImpl.java:27`
- **描述**: `stockIn` 方法未校验 `qty` 是否为正数。传入 `null` 或 `BigDecimal.ZERO` 或负数都不会抛异常，导致无效写入
- **修复建议**: `if (qty == null || qty.compareTo(BigDecimal.ZERO) <= 0) throw new JeecgBootException("入库数量必须大于0")`

### P2-6 SimpleDateFormat 使用（P2）
- **文件**: `MesBatchServiceImpl.java:32`
- **描述**: `new SimpleDateFormat("yyyyMMdd")` 每次调用创建新实例 → 性能可接受（局部变量），但建议用 `DateTimeFormatter`（Java 17+）
- **修复建议**: 提取为 `private static final DateTimeFormatter FMT = DateTimeFormatter.ofPattern("yyyyMMdd")`

### P3-3 状态硬编码枚举值（P3）
- **文件**: 全局 `status "1"/"2"/"3"/"4"`, `originType "1"/"2"/"3"`, `bizType "3"/"4"`
- **描述**: 批次状态/来源类型/业务类型散布在 6 个文件中，无集中枚举定义。改一个值需要全量搜索
- **修复建议**: 定义 `BatchStatusEnum`(1=在用,2=冻结,3=已耗尽,4=过期) 和 `BatchBizTypeEnum`
