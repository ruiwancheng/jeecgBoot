# 06_研发大牛1号_架构全局视角 — MES 批次管理审计

**审计角色**: 研发大牛1号 — 架构全局视角  
**审计日期**: 2026-07-31  

## 审计发现

### P0-1 批次号取号无锁（P0）
- **文件**: `MesBatchServiceImpl.java:33-36`
- **描述**: count+1 模式无任何并发保护。这是编码规则模块已验证的经典反模式（synchronized+@Transactional 发重号）。此处连 synchronized 都没有
- **修复建议**: Mapper 加 `selectBatchNoForUpdate` 带 `FOR UPDATE` 的 SQL，Service 中在事务内调用

### P0-2 MesBatchLedgerMapper 接口方法无 SQL 实现（P0）
- **文件**: `MesBatchLedgerMapper.java:14,19`
- **描述**: MyBatis Mapper 接口声明了 `selectByBatchId` 和 `selectByBiz` 但没有 `@Select` 注解或 XML 映射 → 应用启动时 MyBatis 抛 `BindingException` → 整个 Spring 上下文无法初始化
- **修复建议**: 
  - `selectByBatchId`（未在 Service 中使用）→ 加 `@Select` 或删除
  - `selectByBiz`（在 `MesBatchLedgerServiceImpl.listByBiz` 中被调用）→ 必须加 `@Select`

### P1-1 MesBatch status VARCHAR vs 其他模块 Integer（P1）
- **文件**: `MesBatch.java:67`; `V8.0.0__mes_batch_init.sql:21`
- **描述**: 批次 status 用 `VARCHAR(20)`，但仓库/客户/库位等模块统一用 `Integer`+字典。跨模块不一致导致 QueryGenerator 条件推导不同：Integer 字段处理 `>`/`>=` 范围查询，VARCHAR 走 `eq`/`like`
- **修复建议**: 改为 `Integer` 类型，与项目规范保持一致

### P1-2 c_mes_batch_ledger.warehouse_id NOT NULL 但传空串（P1）
- **文件**: `MesBatchServiceImpl.java:54`; `V8.0.0__mes_batch_init.sql:58`
- **描述**: 创建批次时 `writeLedger(batchId, batchNo, materialId, "", ...)` — warehouseId 传空串。DDL 中 `warehouse_id VARCHAR(32) NOT NULL`，空串不是 NULL 但语义上是"无仓库"
- **修复建议**: DDL 中改 `warehouse_id VARCHAR(32) DEFAULT ''` 或允许 NULL，批次创建的流水仓库留空

### P1-4 MesBatchLedger 无 updateBy/updateTime（P1）
- **文件**: `MesBatchLedger.java:72-76`
- **描述**: 流水实体少了 `updateBy` 和 `updateTime` 字段。流水一旦写入不应被修改，但缺少这两个字段使得审计链不完整
- **修复建议**: 补充字段，或在设计上明确"流水只写不改"不需要这两个字段

### P2-4 stockOutFifo FOR UPDATE 锁全表（P2）
- **文件**: `MesBatchInventoryMapper.java:34-37`
- **描述**: `selectFifoByMaterialForUpdate` 用 `WHERE material_id + warehouse_id + qty>0 ... FOR UPDATE` 锁住同物料同仓库的所有正库存行。如果某种常用物料有 100+ 批次行，每次出库锁 100 行 → 高并发下串行化
- **修复建议**: 分两阶段：先用无锁查询确定需要扣的批次范围，再 FOR UPDATE 锁具体行（锁定前用 `SKIP LOCKED` 跳过已锁行）

### P2-5 索引未覆盖 FIFO 查询（P2）
- **文件**: `V8.0.0__mes_batch_init.sql:49`
- **描述**: 现有 `idx_bi_material_warehouse(material_id, warehouse_id)` 不包含 `qty/del_flag/create_time`。FIFO 查询 `ORDER BY create_time ASC` 可能触发 filesort
- **修复建议**: 建复合索引 `(material_id, warehouse_id, del_flag, qty, create_time, id)`
