# 05_产品大佬3号_资损合规视角 — MES 批次管理审计

**审计角色**: 产品大佬3号 — 资损合规视角  
**审计日期**: 2026-07-31  

## 审计发现

### P0-5 stockOutFifo 返回值被丢弃（P0）
- **文件**: `MesSalesOutboundServiceImpl.java:133`; `ProductionPickingServiceImpl.java:132`
- **描述**: `batchInventoryService.stockOutFifo(...)` 返回 `List<BatchOutDetail>` 含 `batchId/batchNo/qty/unitCost`，但两处调用方都未接收/使用返回值！销售出库明细的 unitCost 字段保持 null——销货成本数据丢失，影响业财一致。
- **修复建议**: 接收返回值：`List<BatchOutDetail> details = batchInventoryService.stockOutFifo(...)`，将批次成本写入明细的 `unitCost` 字段

### P0-2 Mapper 方法无 SQL 实现（P0）
- **文件**: `MesBatchLedgerMapper.java:14,19`
- **描述**: `selectByBiz` 在 `MesBatchLedgerServiceImpl.listByBiz` 中被调用，但无 SQL 实现 → 运行时 `BindingException`
- **修复建议**: 加 `@Select` 或删除未实现的方法

### P1-1 多次入库 unitCost 不更新（P1）
- **文件**: `MesBatchInventoryServiceImpl.java:30-46`
- **描述**: stockIn 仅首次创建库存行时从主档取 unitCost，后续入库跳过 setUnitCost。如果第一次入库成本 10 元，第二次入库成本 12 元 → 库存 unitCost 仍是 10 元
- **修复建议**: 每次入库后按移动平均成本加权更新 `inv.setUnitCost(newAvgCost)`

### P1-2 主库存与批次库存无对账（P1）
- **文件**: 跨模块
- **描述**: `MesInventoryServiceImpl.stockIn/stockOut` 操作主库存，`MesBatchInventoryServiceImpl.stockIn/stockOutFifo` 操作批次库存。两者独立操作，没有 `assert SUM(批次.qty) == 主库存.qty` 的校验
- **修复建议**: 在 batch inventory controller 增加对账接口：`SUM(qty) GROUP BY material_id, warehouse_id` 与 `c_mes_inventory` LEFT JOIN 对比，差异 > 0 时告警

### P2-3 完工入库批次成本为 NULL（P2）
- **文件**: `CompletionReceiptServiceImpl.java:137-141`
- **描述**: `batchService.createBatch(item.getMaterialId(), "2", ..., item.getReceiptQty(), null, null, null)` — unitCost 传 null。意味着完工入库的批次没有成本 → 出库成本为 0 → 销货成本失实
- **修复建议**: 生产完工入库应传入生产成本（BOM 物料成本 + 人工费用分摊），或至少传入当前物料移动平均成本
