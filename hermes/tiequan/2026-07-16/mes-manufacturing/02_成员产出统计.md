## 二、共识判定（多名成员独立识别的同一风险）

### 全体/绝大多数成员一致（≥7 人）—— 最高共识

| 共识风险 | 识别成员 | 共识级别 |
|---|---|---|
| picking/completion 表名不一致（实体 `mes_*` vs 建表 SQL `c_mes_*`），上线即报表不存在 | 05、06、08、09、11、12 + 主控复核 | **6人+复核** |
| 完工入库无累计数量校验，同一订单可反复入库超计划（与 e84c96d 同型漏洞） | 03、05、08、10、12 | **5人** |
| 订单无状态机/状态流转，所有单据永远草稿，编辑强制 setStatus("1") | 03、04、08、12 | **4人+** |
| 领料完全不与 BOM 对账（不校验物料是否在 BOM 子项、不限累计领料量） | 03、05、12 | **3人** |
| 订单 completedQty 是死字段，入库从不回写，进度永远为 0 | 03、06、08、12 | **4人** |

### 多数成员一致（3~4 人）

| 共识风险 | 识别成员 |
|---|---|
| 领料/入库的状态校验方向写反（"仅草稿订单可操作"与真实业务相反） | 03、04、10、12 |
| 库存台账断裂：领料/完工入库均不写 MesInventoryLedger | 05、12 |
| 删除 BOM/订单不检查下游引用，产生悬空外键/孤儿单 | 03、04、10、12 |
| 子表 @TableLogic 与 DDL 缺 del_flag 列矛盾 + 主子表删除策略混用 | 04、06、12 |
| 前后端字段名不一致（BOM isSubstitute vs isAlternative；领料 pickDate vs pickingDate） | 03、04、07、09 |
| 并发竞态：查重-插入非原子、复活逻辑双活、无锁 | 04、08、12 |
| 跨模块走 Mapper 直查（picking/completion 直查 order 表）破坏服务边界 | 06、08 |
| Controller 直接暴露 Entity，createBy/updateBy/delFlag 敏感字段泄露 | 07、09 |

### 单成员独立发现（仍具价值，列入总报告）

- 09 号：菜单权限 sys_permission 未注册（V7.0.x 只有授权没有菜单 INSERT，@RequiresPermissions 全 403）—— **主控已复核属实**
- 06 号：picking/completion 实体冗余字段（productionOrderCode/warehouseName/materialCode 等）SQL 无对应列；completion 子表 SQL 有 plan_qty 实体却无字段
- 11 号：production_order_id 外键无索引、saveItems 逐条 INSERT、先删后插写放大、缺 (status,create_time) 复合索引
- 12 号：全模块无单价/金额字段，成本维度资损无法度量（设计级缺口）

## 三、计数方式说明

1. 按各成员报告中显式标注的 P0/P1/P2 出现次数统计。
2. 同一风险被多人重复识别时重复计数——重复次数本身反映共识强度，已在第二节单列。
3. 约数（~）表示该成员报告以测试用例/检查项形式组织，P 级标注为区间估算。
4. **总报告的结论不采用数字相加**，以第二节共识清单 + 各成员独立重大发现合并去重后形成最终风险清单。
