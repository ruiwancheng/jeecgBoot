### 2）空指针风险

#### P1-1：`getCurrentUsername()` 强转 NPE 风险
**文件：** `bom/service/impl/MesBomServiceImpl.java:152-154`、`picking/service/impl/ProductionPickingServiceImpl.java:159-161`、`completion/service/impl/CompletionReceiptServiceImpl.java:161-163`

```java
private String getCurrentUsername() {
    try { return ((LoginUser) SecurityUtils.getSubject().getPrincipal()).getUsername(); }
    catch (Exception e) { return "system"; }
}
```
**风险：** `SecurityUtils.getSubject().getPrincipal()` 在异步线程/无登录态时返回 `null`，强转 `LoginUser` 会抛 `ClassCastException` 或 `NullPointerException`。虽然外层 `catch (Exception)` 兜底返回 `"system"`，但异常被完全吞掉，无法感知未登录/上下文丢失的真实问题。

**修复建议：**
```java
Object principal = SecurityUtils.getSubject().getPrincipal();
if (principal instanceof LoginUser) {
    return ((LoginUser) principal).getUsername();
}
return "system";
```
并记录 `log.warn("获取当前用户失败，使用默认 system")`。

#### P2-1：`getById` 后判空完整
- `ProductionOrderController.queryById`：`e != null ? Result.ok(e) : Result.error("订单不存在")` ✅
- `MesBomServiceImpl.queryWithItems`：`bom != null` 判空 ✅
- `ProductionPickingServiceImpl.queryWithItems`：`picking != null` 判空 ✅
- `CompletionReceiptServiceImpl.queryWithItems`：`receipt != null` 判空 ✅
- `checkStatus` 私有方法：`exist != null` 判空 ✅

#### P2-2：前端可选链/容错
- `BomDrawer.vue:66`、`PickingDrawer.vue:58`、`CompletionReceiptDrawer.vue:62` 使用 `items.value = xxx?.length ? ... : [...]` 容错 ✅
- `JSearchSelect` 的 `v?.value || v` 处理 ✅

### 3）异常处理与事务

#### P1-2：`removeByIds` 批量删除非原子性风险
**文件：** `MesBomServiceImpl.java:93-105`、`ProductionPickingServiceImpl.java:98-110`、`CompletionReceiptServiceImpl.java:98-110`

```java
@Override @Transactional(rollbackFor = Exception.class)
public boolean removeByIds(Collection<?> list) {
    ...
    itemMapper.delete(delQw);   // 先删子表
    return super.removeByIds(list); // 后删主表
}
```
**风险：** 若 `super.removeByIds(list)` 因数据库约束（如外键、触发器）失败，事务会回滚，子表删除也会回滚，这一点 `@Transactional` 能兜住。但问题是 `removeByIds` 没有校验主表状态，且 `super.removeByIds` 是 MyBatis-Plus 的批量逻辑删除，若其中某条主表记录不存在或已被删除，不会抛异常，会导致“子表已删、主表未删”的假象（实际回滚）。更严重的是，`removeByIds` 没有调用 `checkStatus`，与 `removeWithItems` 的行为不一致。

**修复建议：**
1. 在 `removeByIds` 中增加主表状态校验（与单条删除一致）；
2. 或改为 `removeWithItems` 的批量版本，逐条调用 `removeWithItems` 并在循环外统一事务。

#### P1-3：`queryWithItems` 未加只读事务
**文件：** `MesBomServiceImpl.java:30-39`、`ProductionPickingServiceImpl.java:35-44`、`CompletionReceiptServiceImpl.java:35-44`

```java
@Override
public MesBom queryWithItems(String id) { ... }
```
**风险：** 未加 `@Transactional(readOnly = true)`，在 MySQL 默认隔离级别下，先查主表再查子表，若中间有并发写入，可能出现主表已更新但子表未更新的中间态（虽然业务影响较小，但不符合 JeecgBoot 规范）。

**修复建议：**
```java
@Transactional(readOnly = true)
public MesBom queryWithItems(String id) { ... }
```

#### P2-3：`try-catch` 未吞异常
- `saveWithItems` 中 `catch (DuplicateKeyException e)` 明确转换为业务异常 `JeecgBootException` ✅
- `getCurrentUsername` 中 `catch (Exception e)` 返回 `"system"`，属于兜底但吞了异常上下文（已在 P1-1 提及）⚠️

### 6）数据字典

#### P0-1：picking/completion 实体缺少 `@Dict` 注解，列表页字典文本无法解析
**文件：**
- `picking/entity/MesProductionPicking.java:32-50`
- `completion/entity/MesCompletionReceipt.java:31-49`

```java
@Excel(name = "生产订单号", width = 20)
@Schema(description = "生产订单ID")
private String productionOrderId;

@Excel(name = "仓库ID", width = 20)
@Schema(description = "仓库ID")
private String warehouseId;

@Excel(name = "状态", width = 15, dicCode = "yn")
@Schema(description = "状态：1-草稿")
private String status;
```
**风险：** 前端 `picking.data.ts:6-9`、`completion.data.ts:6-10` 使用 `productionOrderId`、`warehouseId_dictText`、`status_dictText` 展示，但后端实体未加 `@Dict` 注解，JeecgBoot 的 `DictAspect` 不会自动翻译，导致列表页显示 ID 或空白。

**修复建议：**
```java
@Dict(dictTable = "c_mes_production_order", dicText = "code", dicCode = "id")
private String productionOrderId;

@Dict(dictTable = "c_mes_warehouse", dicText = "name", dicCode = "id")
private String warehouseId;

@Dict(dicCode = "mes_picking_status") // 或 mes_completion_status
private String status;
```

**文件：** `picking.data.ts:16,25`、`completion.data.ts:17,27`

| 页面 | 前端 dictCode | SQL 实际字典 | 是否匹配 |
|------|---------------|--------------|----------|
| picking | `mes_picking_status` | `mes_picking_status` | ✅ |

字典编码本身匹配，但 picking/completion 实体缺少 `@Dict` 注解导致 `status_dictText` 无法生成（见 P0-1）。

#### P1-4：`isSubstitute` 字段命名不一致
**文件：** `bom/entity/MesBomItem.java:30`、`bom/BomDrawer.vue:18-19,45,58,66`

- 实体字段：`isSubstitute`（`@Schema(description = "是否替代料")`）
- SQL 字段：`is_substitute VARCHAR(1) DEFAULT '0' COMMENT '是否替代料(yn)'`

**修复建议：** 统一为 `isSubstitute`，前端同步修改；或后端加 `@TableField("is_substitute")` 并改字段名为 `isSubstitute`，前端保持一致。

#### P2-4：BOM 子项 `materialId` 字典注解正确
`MesBomItem.java:27` 有 `@Dict(dictTable = "c_mes_material", dicText = "name", dicCode = "id")` ✅

### 7）VO 与实体映射

#### P0-3：直接暴露 Entity，未使用 VO/PageVO 隔离敏感字段
**文件：** 全部 Controller 的 `queryPageList`、`queryAll`、`queryById`、`exportXls`

```java
@GetMapping("/list")
public Result<IPage<MesProductionOrder>> queryPageList(...) { ... }

@GetMapping("/queryAll")
public Result<List<MesProductionOrder>> queryAll() { ... }
```
**风险：**
1. 实体包含 `createBy`、`createTime`、`updateBy`、`updateTime`、`delFlag`，全部返回给前端；
2. `exportXls` 使用 `super.exportXls(req, entity, MesProductionOrder.class, ...)`，Excel 导出同样包含全部字段；
3. 未使用 `@JsonIgnore` 或 VO 过滤，存在敏感信息泄露。

**修复建议：**
1. 新增 `MesProductionOrderVo extends MesProductionOrder`，用 `@JsonIgnore` 隐藏 `createBy/updateBy/delFlag`；
2. 或 Controller 返回 `IPage<MesProductionOrderVo>`，Service 层做 `BeanUtils.copyProperties` 转换；
3. `exportXls` 前手动设置查询字段，排除敏感列。

#### P1-5：`transient` 与 `@TableField(exist = false)` 混用
**文件：** `bom/entity/MesBom.java:41`、`picking/entity/MesProductionPicking.java:76`、`completion/entity/MesCompletionReceipt.java:75`

- `MesBom.items` 使用 `private transient List<MesBomItem> items;`
- `MesProductionPicking.items` / `MesCompletionReceipt.items` 使用 `@TableField(exist = false)`

**风险：** `transient` 在 Java 序列化时会被忽略，但 Jackson/FastJSON 默认仍会序列化；而 `@TableField(exist = false)` 明确告知 MyBatis-Plus 不映射数据库。混用风格不统一，且 `transient` 在 RPC 序列化场景下可能丢失数据。

**修复建议：** 统一改为 `@TableField(exist = false)`，移除 `transient`。
