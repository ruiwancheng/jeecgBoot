## 一、静态检查结论速览

| # | 边界场景 | 后端校验 | 前端校验 | 总体 |
|---|---------|---------|---------|------|
| 1 | 空行/空子表 | ✅ 三类主子表均拦截 | ⚠️ 前端强制至少 1 行但可提交空行 | 基本满足 |
| 2 | 负数/零数量 | ✅ 全部拦截（`>0` 校验） | ⚠️ InputNumber min 可绕过 | 满足（以后端为准） |
| 3 | 超大数量（超 DECIMAL(18,4)） | ❌ 无精度/上限校验，靠 DB 报错 | ❌ 无 max 限制 | **不满足** |
| 4 | 必填缺失 | ✅ 后端基本覆盖，入库单仓库仅前端必填 | ⚠️ 部分字段后端不校验 | 部分满足 |
| 5 | 主子表不一致（伪造主表 ID） | ❌ 不校验子表 bomId/pickingId/receiptId | — | **不满足（可被篡改）** |
| 6 | 删除已引用数据 | ❌ BOM 被订单引用可删；订单有领料/入库记录可删 | — | **不满足** |
| 7 | 状态异常（删后再操作） | ⚠️ 编辑/删除有状态校验，但逻辑删除记录编辑时不拦截 | — | 部分满足 |
| 8 | 并发重复提交（双击保存） | ⚠️ 靠 DB 唯一索引兜底，可能复活已删单或抛 500 | ❌ 前端无防重（confirmLoading 时机缺陷） | **部分不满足** |

### 8. 并发重复提交（双击保存按钮）

| 用例编号 | 测试项 | 操作步骤 | 预期结果 | 当前代码是否满足 |
|---------|--------|---------|---------|----------------|
| BE-08-01 | 前端双击"确定"保存 BOM | 快速双击抽屉确定按钮 | 只产生 1 条记录 | ⚠️ **部分满足（有缺陷）**。`BomDrawer.vue` `handleSubmit` L80-87：`setDrawerProps({ confirmLoading: true })` 在 `await validate()` **之后**才设置——validate 是异步的，若校验耗时（字典加载等），校验期间按钮未 loading，双击仍触发两次 `handleSubmit`。两个请求都进入后端 |
| BE-08-02 | 后端唯一约束兜底双击 | 两个并发 add 同 code 请求 | 第二个请求友好拒绝"编号已存在" | ⚠️ **部分满足**。`saveWithItems` 先 `selectCount` 查重再 insert——**存在 TOCTOU 竞态**：两请求同时通过查重（count=0），同时 insert。此时依赖 DB 唯一索引：BOM 表唯一索引是 `uk_bom_product_version(product_id, version, del_flag)`——**code 无唯一索引**！双击同 code 不同 version 可产生两条同 code BOM。order/picking/completion 有 `uk_*_code(code, del_flag)` 唯一索引兜底，第二个请求抛 DuplicateKeyException → 捕获转"编号已存在"✅，但 del_flag 参与索引意味着逻辑删除后同 code 可再 insert（设计如此，配合 resurrect） |
| BE-08-03 | 双击触发 resurrect 竞态 | 已删 code=X 的 BOM，双击 add code=X | 一个 resurrect 成功，另一个拒绝 | ⚠️ 竞态：两请求都查 active count=0、都查到 deleted old，都执行 resurrect（update ... where id），第二次 update 覆盖第一次——**两次都"成功"**，后写覆盖先写，子项可能重复插入（两事务都 itemMapper.insert 同 bom_id 的新子项，无唯一约束）→ **子项翻倍** |
| BE-08-04 | 前端无防抖/无提交中标志 | 检查四个 Drawer | 应有 submitting ref 或立即 loading | ❌ **不满足**。四个 Drawer 的 handleSubmit 均为：`await validate()` → 设 loading → `await save`。无前置 submitting 标志位、无防抖。`OrderDrawer.vue` 同样模式（L36-44） |
| BE-08-05 | 双击编辑（edit）同记录 | PUT edit 双击 | 幂等 | ✅ 基本满足。edit 是覆盖式更新+子表先删后插，同事务内重复执行结果一致（竞态下两事务串行后结果等价） |
| BE-08-06 | 网络重试/刷新重提 | 提交后响应慢，用户刷新页面重新提交同单 | 拒绝重复单号 | ⚠️ 同 BE-08-02，BOM 因缺 code 唯一索引存在重复风险，其余三单有唯一索引兜底 |

## 四、执行建议

1. **动态验证优先级**：BE-05-07（孤儿子项）、BE-06-01/02（悬空引用）、BE-08-02/03（并发重复）三项建议优先搭建接口级动态复现（Postman/JMeter 并发），静态推断已较明确但需实测确认 DB 行为（尤其 MySQL sql_mode 是否严格）。
2. **回归基线**：第 1、2 类（空子表、负数）后端校验齐全，可作为冒烟回归基线用例直接自动化。
3. 本报告基于静态走查，未执行系统；标注"满足"的用例在动态环境中仍建议抽查 1~2 条确认异常以 Result.error 形式返回（JeecgBootException 全局处理）而非 500 堆栈。
