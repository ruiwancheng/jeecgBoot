**最严重的阻断性问题（会导致功能直接不可用）：**
1. **实体表名与建表 SQL 不一致**：`MesProductionPicking` 用 `@TableName("mes_production_picking")`、`MesCompletionReceipt` 用 `@TableName("mes_completion_receipt")`，但 SQL 建的是 `c_mes_production_picking` / `c_mes_completion_receipt`（BOM、Order 用 `c_mes_` 前缀，实体也一致）。→ picking / completion 所有 SQL 会报表不存在。
2. **领料日期字段不一致**：后端实体字段 `pickDate`（→ 列 `pick_date`），SQL 建表列是 `picking_date`，前端用 `pickingDate`。三方不一致，字段无法映射。
3. **BOM 子表“替代料”字段不一致**：后端实体 `isSubstitute`（列 `is_substitute`），前端 Drawer 用 `isAlternative`。保存时该字段丢失。
4. **完工入库明细缺字段**：SQL 明细表有 `plan_qty`，但 `MesCompletionReceiptItem` 实体没有 `planQty` 字段（前端子表却在编辑 planQty），该列不会被保存/回显。
5. **权限菜单未注册**：V7.0.x SQL 只做 `sys_role_permission` 授权（引用了 `mes_bom`、`mes:bom:%` 等 ID），但**没有任何 `INSERT INTO sys_permission` 菜单/权限注册语句**，菜单与权限点在数据库里不存在，`@RequiresPermissions` 会全部 403。

## 1. 增删改查（CRUD）

四模块 Controller 均继承 `JeecgController`，并提供 list / queryById / add / edit / delete / deleteBatch / queryAll / exportXls。Service 层对“草稿(status=1) 才能编辑/删除”做了校验，编号唯一性（含逻辑删除后复活 resurrect）也有处理，单表 CRUD 设计合理。

|---|--------|----------|----------|

| # | 测试项 | 后端权限码 | 前端 | 静态判断 |
|---|--------|-----------|------|----------|
| 5.1 | BOM | `mes:bom:list/add/edit/delete/deleteBatch/export` | **无 v-auth / auth 指令**，按钮恒显示 | ❌ 前端未做按钮级权限控制，仅依赖后端拦截 |

| 5.3 | 领料 | `mes:productionPicking:list/add/edit/delete/deleteBatch/export` | 同上 | ❌ 同上 |
| 5.4 | 入库 | `mes:completionReceipt:list/add/edit/delete/deleteBatch/export` | 同上 | ❌ 同上 |
| 5.5 | 权限点注册 | 数据库 sys_permission 应存在上述 perms | V7.0.x SQL 只有 `sys_role_permission` 授权，**无 `INSERT INTO sys_permission` 注册菜单/权限点** | ❌ 阻断：权限点不存在，`@RequiresPermissions` 校验时无对应授权数据，所有接口 403；角色授权 SQL 也因匹配不到记录而成为空操作 |

## 7. 其他静态发现（供参考）

1. **picking/completion 实体缺 `@JsonFormat`**：pickDate / receiptDate / createTime 等日期字段未加 `@JsonFormat(timezone="GMT+8", pattern=...)`，序列化可能输出时间戳或时区偏移（BOM/Order 已加）。
2. **picking/completion 实体冗余字段设计不一致**：同时存在 `productionOrderId` 与 `productionOrderCode`、`warehouseId` 与 `warehouseName`，但保存逻辑（`saveWithItems`）从未回填 code/name，冗余列始终为空。
3. **completion 主表实体缺 `productId` 字段**：SQL `c_mes_completion_receipt` 有 `product_id` 列，实体没有，前端表单却在提交 productId → 数据丢失。
4. **queryAll / exportXls 1000 条上限**：`service.count()` 统计的是未逻辑删除总数，逻辑正确，属保护性设计。
5. **前端删除后直接 `message.success`**：未捕获后端业务异常（如非草稿禁止删除）时，异常会由全局 axios 拦截器提示，可接受，但 UX 上建议 await 失败不刷新。

## 8. 修复优先级建议（仅建议，不在本任务修改）

| 优先级 | 问题 | 建议 |
|--------|------|------|
| P0 | picking/completion 表名少 `c_mes_` 前缀 | 统一 `@TableName("c_mes_production_picking")` / `@TableName("c_mes_completion_receipt")`（含 item） |
| P0 | 权限菜单未注册 | 在 V7.0.x SQL 中补充 `INSERT INTO sys_permission`（菜单+按钮 perms） |
| P1 | pickDate / pickingDate / picking_date 三方不一致 | 统一为 `pickingDate` ↔ `picking_date` |
| P1 | BOM 子表 isSubstitute vs isAlternative | 统一字段名与类型（String '0'/'1'） |
| P1 | completion 明细缺 planQty、主表缺 productId | 实体补字段并与 SQL 对齐 |
| P2 | picking/completion 字典注解缺失或 dicCode 错误 | 补 `@Dict(dicCode="mes_picking_status"/"mes_completion_status")`，修正 @Excel dicCode，补 warehouseId/productId 的 dictTable 注解 |

| P3 | 无 Excel 导入 | 如需导入，Controller 增加 importExcel 重写 + 前端导入按钮 |
