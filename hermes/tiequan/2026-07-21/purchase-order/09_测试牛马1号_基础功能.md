# 铁拳团审计报告 — 采购订单模块（09 测试牛马1号 · 基础功能）

> 审计视角：正向/逆向流程、增删改查完整性、状态流转合理性、主子表联动
> 审计范围：后端 purchase/order 全量（Entity×2/Mapper×2/ServiceImpl/Controller）、前端 views/project/mes/purchase/order 全量、V6.0.1 SQL
> 审计日期：2026-07-21

## 结论

主子表 CRUD 与金额/税额后端强制重算做得扎实（级联保存、级联删除、编号唯一+复活机制、审核守护 SQL 均在），但**正向流程在界面上走不通**：前端没有"审核"入口，订单永远无法离开草稿状态，下游到货流程被整体阻断；同时状态机只有 1→3 一步，待确认/已关闭状态不可达、无反审核无关闭，逆向流程完全缺失。

## Findings

| 级别 | 位置 | 问题 | 影响 | 建议 |
|------|------|------|------|------|
| P0 | 前端 index.vue `getActions()` + order.api.ts | **无审核入口**：操作列只有"编辑/删除"，api 文件没有 audit 函数，后端 `/audit` 接口从界面无法触发 | 订单永远停留在"草稿"，无法审核确认，采购收货等下游单据无单可引，正向主流程在界面上整体断链 | index.vue 增加"审核"按钮（仅 status='1' 时显示，二次确认），order.api.ts 补 `auditOrder` 函数调用 PUT `/audit` |
| P1 | 前端 OrderDrawer.vue 第 64 行 | **缺少 import**：使用了 `getNextCode` 和 `MES_BIZ_CODE` 但未导入（对比 sales/order/OrderDrawer.vue 第 54-55 行有导入；项目无 auto-import 插件） | 运行时 ReferenceError 被外层 try/catch 静默吞掉，新增订单时自动编码功能完全失效且无任何提示，用户只能手输编号，编号规则形同虚设 | 补上两行 import；此类静默 catch 建议至少 console.warn |
| P2 | 后端 ServiceImpl `audit()` + Mapper `auditWithGuard` + SQL 字典 | **状态机跳跃且残缺**：审核直接把状态 1(草稿) 改为 3(已确认)，字典中的 2(待确认) 永远无法到达；无"提交确认"接口使 2 成为死状态 | 状态字典与程序行为不一致，后续按状态统计/筛选会误导业务 | 要么审核走 1→2→3 两步并补"确认"接口，要么从字典删掉"待确认" |
| P2 | 后端 Controller/Service | **逆向流程缺失**：无反审核、无关闭接口；审核后订单既不能改也不能删（checkStatus 拦截），状态 6(已关闭) 不可达 | 审核后发现录错（供应商选错、金额录错）时业务上无任何补救手段，只能找技术人员改库 | 增加"反审核"（3→1，需校验无下游收货单）和"关闭"（1/3→6）接口及对应前端按钮 |
| P2 | 后端 ServiceImpl `updateWithItems` / `removeWithItems` / `checkStatus` | **状态校验与写入分离，存在并发窗口**：先 select 查状态再 update/delete，审核（auditWithGuard）恰好在窗口内提交时，编辑会把已确认订单的 status 覆盖回 '1'（`entity.setStatus("1")` + updateById 全字段更新），删除会删掉已确认订单 | 并发下出现"已确认订单被改回草稿/被删除"的数据事故 | 编辑/删除的写入也走带守护条件的 SQL（`WHERE id=? AND status='1'`，影响行数=0 则抛错），与 auditWithGuard 同款模式 |
| P2 | 前端 index.vue `getActions(record)` | **操作按钮不按状态控制**：非草稿订单同样显示"编辑/删除"，点击后才被后端报错拒绝 | 用户体验差，且容易让业务误以为系统出错 | 按 `record.status` 动态返回操作项：仅草稿显示编辑/删除，已确认显示审核相关操作 |
| P2 | 前端 OrderDrawer.vue itemColumns + 后端 `validateOrder` | **订单行税率无法录入**：行编辑表格只有物料/数量/单价/金额，无税率列；后端默认 0.13，但 calcTotal 明确支持逐行多税率 | 非 13% 税率（如 9%、免税）的采购业务税额、含税总额全部算错，且用户无法修正 | 行表格增加税率列（InputNumber 0~1，精度 2），与后端逐行计税逻辑对齐 |
| P3 | 后端 ServiceImpl `saveWithItems` resurrect 分支 | **复活不校验影响行数**：`resurrect()` 返回 void；两请求并发复活同一已删编号时，失败方 UPDATE 0 行仍继续 `saveItems`，向同一订单重复插入明细行 | 极端并发下订单行翻倍、金额翻倍 | resurrect 改为返回 int 并校验=1，失败抛"编号已被占用" |
| P3 | 后端 ServiceImpl `updateWithItems` 编号改重 + SQL `uk_po_code_del(code, del_flag)` | **边界场景撞唯一索引**：编辑时把编号改成某"已删除历史订单"的编号（唯一索引允许：一个 del_flag=0 一个=1），之后再删除该订单时逻辑删除置 del_flag=1 与历史行冲突，抛 DuplicateKeyException 500 | 低频但一旦发生该订单永远无法删除 | 编辑改编号时也校验"已删除同编号"并走复活/或拒绝；或唯一索引改为 code 单字段+删除时改写 code |
| P3 | 前端 index.vue | **无批量删除 UI**：后端 deleteBatch 与 removeByIds 批量守护都已实现，前端表格未开 rowSelection、无批量删除按钮 | 功能做了但用不上，批量清理草稿单只能逐条点 | 表格加 rowSelection 与批量删除按钮，调用 deleteBatchOrder |
| P3 | 前端 OrderDrawer.vue `removeLine`/`addLine` | **删行后 lineNo 不重排**：中间删行再新增会出现 lineNo 重复，而行表格 `rowKey="lineNo"` | Vue 渲染告警、行状态可能串位（后端提交时会按 i+1 重排，数据本身正确） | removeLine 后遍历重排 lineNo |
| P3 | 前端 OrderDrawer.vue 金额列 | 行金额用 JS 浮点 `(qty*price).toFixed(2)` 即时展示，后端用 BigDecimal HALF_UP 重算 | 个别数值下展示金额与保存后金额差 0.01，用户困惑（仅展示层，入库值以后端为准） | 展示列也提示"以后端计算为准"或用 decimal 库 |
| P3 | 前端 order.data.ts searchFormSchema | 查询区"供应商"是普通 Input 需手输供应商 ID；"订单日期"非必填（前后端均未要求） | 业务人员不可能记得 ID，查询条件实际不可用；日期缺失影响交货预警类后续功能 | 查询条件供应商改用 JSearchSelect（同表单）；评估订单日期设为必填 |

## 正向验证记录（通过项）

- 增：saveWithItems 强制草稿状态防 API 绕过、编号查重+已删复活、DuplicateKeyException 兜底、事务完整 ✔
- 删：单删/批量删均校验草稿状态、主从级联删除、批量改批量 SQL 无自调用事务问题 ✔
- 改：全删全插订单行避免行级 diff 复杂性、编号唯一校验排除自身 ✔
- 查：queryWithItems 行按 lineNo 排序、列表分页、queryAll/导出 1000 条熔断 ✔
- 金额：后端强制重算行金额（数量×单价）与逐行税额（行金额×行税率），不信任前端传值 ✔
- 校验：编号/供应商必填、编号长度、交货日期≥订单日期、至少一行、数量>0、单价≥0 均有后端校验 ✔
- 审核接口本身：auditWithGuard 守护 SQL 防重复审核，幂等安全 ✔
