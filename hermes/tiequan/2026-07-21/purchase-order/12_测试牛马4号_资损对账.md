# 铁拳团审计报告 — 采购订单模块（测试牛马4号：资损对账视角）

- 审计日期：2026-07-21
- 审计范围：后端 `purchase/order/` 全部（Entity×2 / Mapper×2 / ServiceImpl / Controller）、前端 `views/project/mes/purchase/order/`（index.vue / OrderDrawer.vue / order.api.ts / order.data.ts）、SQL `V6.0.1__mes_purchase_order_init.sql`；为验证三单对账链路，延伸只读核对了 `purchase/receipt`（入库）、`finance/payable`（应付）、`basic/MesInventoryServiceImpl`（库存台账）。
- 视角：金额一致性（订单 vs 收货 vs 应付）、数量一致性、库存准确性、状态回写正确性。

## 结论

订单→入库→应付的对账链路存在 1 个 P0 资损漏洞（订单外物料可入库：库存增加但应付不计），且订单状态在入库审核后永不回写"部分到货/已到货"，订单执行闭环断裂；应付税额硬编码 13% 与订单行级税率机制冲突，多税率场景下订单税额与应付税额必然对不上。

## Findings

| 级别 | 位置 | 问题 | 影响 | 建议 |
|------|------|------|------|------|
| P0 | receipt/service/impl/MesPurchaseReceiptServiceImpl.java `validateReceipt` 超量校验段 + `audit` 取价段 | **订单外物料可入库**：入库行物料不在采购订单中时，`orderQtyMap.get()` 返回 null 直接跳过校验；审核时价格匹配不到（orderItems 为空）则静默跳过金额计算，但 `inventoryService.stockIn` 照常执行 | 库存实物增加、应付金额不含该行 → 仓库有货、财务无账，直接资损；且无法通过应付对账发现 | 保存入库单时强制校验"每行物料必须存在于关联采购订单"，不在订单中的物料直接拒绝；审核时对取不到订单单价的行抛异常而非静默跳过 |
| P0 | order/service/impl + receipt/audit（全链路） | **订单状态回写缺失**：入库审核完成后没有任何代码把采购订单状态从 '3'(已确认) 推进到 '4'(部分到货)/'5'(已到货)（全仓 grep 无 c_mes_purchase_order 的 4/5 写入）；字典里定义了 4/5/6 但均为死状态 | 订单永远停在"已确认"，按状态统计的到货进度/订单执行率报表全部失真，三单对账无法闭环；长期挂账无法区分"未发货"与"已收完" | 入库审核事务内按"累计已入库量 vs 订单量"回写订单状态（部分→4，足量→5）；补充"关闭订单"入口写入状态 6 |
| P1 | receipt/audit 应付生成段 `ap.setTaxAmount(totalAmount.multiply(new BigDecimal("0.13")))` | **应付税额硬编码 13%**：订单侧 `calcTotal` 支持行级税率（taxRate 可传任意值），但应付生成时无视订单行实际税率一律乘 0.13 | 含 9%/6%/0% 税率行的订单，订单税额 ≠ 应付税额，业财对账必现差异；税率越低差异越大 | 从订单行取实际 taxRate 逐行算税额；或应付表存 sourceBillId 关联后按订单税额比例分摊 |
| P1 | 前端 order/index.vue `getActions` | **列表无"审核"按钮**：后端 `/mes/purchase/order/audit` 已存在且有权限码，但前端只有编辑/删除两个操作，无审核入口 | 用户无法通过 UI 把订单从草稿推进到已确认 → 入库单创建被"订单状态不允许入库"拦截 → 采购全流程在 UI 层断流（只能调 API 绕过） | 列表行操作加"审核"按钮（仅草稿状态显示），调用 audit 接口 |
| P1 | 全链路（receipt 删除策略 + inventory） | **已审核入库无红冲/退库机制**：入库单只有草稿可删，审核后库存只增不减，采购侧没有任何反向出库入口 | 入库录入错误（数量/仓库/物料错）无法纠正，库存账实永久性不符，只能靠后续盘点硬调 | 提供"红冲入庫单"功能：生成负向入库单冲减库存与应付，保留原单痕迹 |
| P2 | receipt/audit 应付生成段 `ap.setAmount(totalAmount)` | **应付金额口径为不含税**：应付 amount/unsettledAmount = Σ(入库数量×订单单价)（不含税），而订单对客口径是 totalWithTax（含税）；供应商结算通常按含税价 | 订单含税总额 vs 应付合计天然差一个税额，对账报表需人工解释；若财务按应付金额付款则少付税款引发供应商纠纷 | 明确口径：要么应付 amount 改为含税总额（税额单列展示），要么在对账报表中显式标注"应付为不含税口径" |
| P2 | receipt `validateReceipt`/`audit` 按 materialId 匹配订单行 | **订单行未做行级关联**：入库行只存 materialId 不存 orderItemId；订单含重复物料行时 `orderQtyMap` 合并策略 `(a,b)->a` 只保留首行数量，审核取价 `orderItems.get(0)` 也只取首行单价 | ① 同物料两行不同价时超量校验基准错误（少算订单总量→误拦；或按错价核金额）；② 三单对账只能按物料聚合，无法逐行核销 | 入库行增加 order_item_id 字段，保存时强制选行；超量校验与取价均按行级关联 |
| P2 | receipt `validateReceipt` 历史统计段 | **历史入库量统计包含草稿单**：`existingReceipts` 查询不按 status 过滤，废弃未删的草稿入库单会占用数量额度，阻塞后续真实入库（误报"累计入库量超过采购数量"） | 业务阻塞：同事建了草稿没删，后面的人永远入不了库，且报错信息不提示是草稿占用 | 历史统计只算已审核（status='2'）单据，或把草稿占用量单独提示 |
| P2 | order/service/impl `checkStatus` + `updateWithItems` | **编辑不存在的订单产生孤儿明细**：`checkStatus` 在 exist==null 时放行，`updateById` 影响 0 行不报错，随后 `saveItems` 把明细行插到不存在的 orderId 下 | c_mes_purchase_order_item 出现无头明细，按订单 join 对账时明细丢失/总额对不上 | updateWithItems 开头校验订单必须存在，不存在直接抛"订单不存在" |
| P2 | 前端 OrderDrawer.vue `useDrawerInner` | **使用了未导入的 `getNextCode` / `MES_BIZ_CODE`**：import 列表中无这两个符号，运行期 ReferenceError 被 try/catch 静默吞掉 | 新增订单自动编号功能静默失效，用户只能手输编号，撞号率上升（编号冲突直接导致保存报错） | 补 import（参考其他模块如 apply/receipt 的写法），或删除该死代码 |
| P3 | receipt/audit 应付生成段 | **应付到期日固定 +30 天**：`creditPeriod=30`、`dueDate=now+30d`，无视订单上的 paymentTerms（付款条款）字段 | 付款条款形同虚设，应付账龄/到期提醒全部按 30 天算，资金计划失真 | 解析 paymentTerms 或在订单上增加结构化账期天数字段并带入应付 |
| P3 | inventory `stockIn` 调用点（receipt/audit） | **台账 bizId 传的是单据编号 code 而非单据 ID**：`stockIn(..., "采购入库", e.getCode())` | 台账与源单对账需按 code 反查（code 无唯一约束之外的保障，且 resurrect 复用 id/code），跨模块对账口径不统一 | bizId 统一传单据主键 id，另加 bizNo 字段存编号 |
| P3 | 前端 OrderDrawer.vue 金额列 | **行金额预览用 JS 浮点乘法** `(qty*price).toFixed(2)`，与后端 BigDecimal HALF_UP 舍入规则在边界值上可能差 1 分 | 用户看到的预览金额与保存后实际金额偶尔不符，引发对账疑问（后端强制重算，数据本身正确） | 预览文案标注"以后端计算为准"，或用 decimal 库对齐舍入规则 |
| P3 | order `auditWithGuard`（1→3） | **状态 '2'(待确认) 为死状态**：字典定义了"待确认"但审核直接 1→3，无任何代码写入 2 | 状态字典与实际流转不符，按状态过滤的报表少一档 | 要么补"提交确认"动作（1→2→3），要么从字典删除状态 2 |

## 对账链路验证摘要（延伸核对）

- **订单金额自洽**：✅ 后端强制重算行金额（数量×单价）与逐行税额合计，前端传值不可篡改金额，多税率订单内自洽。
- **入库不超量（正常路径）**：✅ 保存/编辑时按"历史（含草稿）+ 本次 ≤ 订单量"校验，审核有状态守卫 + 行锁，同事务回滚保护库存。
- **应付幂等**：✅ `AP-入库单号` 唯一键 + DuplicateKeyException 兜底，重复审核不会产生重复应付。
- **库存台账**：✅ selectForUpdate 行锁 + upsert delta + 台账期初/期末快照，并发入库数量准确。
- **主要断点**：订单外物料入库（P0）、订单状态不回写（P0）、应付税额口径（P1）三处导致三单对账无法全自动闭环，建议优先修复。
