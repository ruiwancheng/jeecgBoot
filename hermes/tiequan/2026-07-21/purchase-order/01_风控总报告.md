## 共识 P0（多视角命中 + 人工核实）

### P0-1：采购订单在页面上永远无法审核，主流程断通（6 视角命中）
- **位置：** 前端 `index.vue` getActions 只有编辑/删除；`order.api.ts` 无 auditOrder 封装
- **核实：** ✅ 属实。后端 `PUT /mes/purchase/order/audit` 存在且收货单校验要求订单状态=已确认(3)——没有审核入口，下单→收货主流程在界面上走不通
- **修法：** 列表加"审核"按钮（仅草稿显示）+ api 封装 + 按钮按状态显隐

### P0-2：三个单据抽屉自动编号静默失效（7 视角命中，总调度认领）
- **位置：** `purchase/order`、`manufacturing/order`、`sales/delivery` 三个 OrderDrawer/DeliveryDrawer 调用了 `getNextCode(MES_BIZ_CODE.XXX)` 但**缺 import**
- **核实：** ✅ 属实，且是总调度在编码规则任务中的引入缺陷（编辑重试时漏了 import 块）。ReferenceError 被 try/catch 吞掉 → 静默失效不报错，此前的 SFC 编译检查覆盖不到
- **修法：** 每个文件补 2 行 import（共 3 个文件）；审计只审了采购订单，另 2 个文件是总调度自查发现的

### P0-3：编辑/删除并发击穿——已审核订单可被改回草稿/被删（5 视角命中）
- **位置：** `updateWithItems`/`removeWithItems` 是"先查状态再写"两步非原子；且编辑强制 `setStatus("1")`
- **核实：** ✅ 属实。与审核并发时，已确认订单被静默改回草稿并整体替换明细；审核用的 auditWithGuard 是正确写法，但编辑/删除没用同款
- **修法：** 编辑/删除改带状态守卫的原子 SQL（`WHERE id=? AND status='1'`，影响 0 行即报错）；编辑不回写 status

### P0-4：收货校验两处漏洞，库存与应付可对不上（2 视角各报 P0，主题一致）
- **a) 超收竞态（研发3号）：** 超收校验"先汇总历史→比较→插入"全程无锁，并发双单可双双通过 → 超收
- **b) 订单外物料可入库（测试4号）：** 入库行物料不在订单中时校验直接跳过，库存照增、应付不含该行 → 有货无账
- **修法：** 涉及收货模块改造（行级 received_qty 原子扣减 + 强制订单内物料），**建议单独立项**，见"处置建议"
