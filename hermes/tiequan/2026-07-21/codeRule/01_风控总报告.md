## 共识问题（≥2 视角检出 → 必改）

### P1-A：取号并发窗口期可发重号（3 视角共识：产品2号/研发3号/测试2号）
- **位置：** `MesCodeRuleServiceImpl.nextCode`
- **机理：** `synchronized` 在 `@Transactional` 代理内层，锁释放早于事务提交 → 并发线程读到未提交的旧流水号，两人拿同一编码。
- **现状兜底：** 业务表 code 唯一约束拦截（重复方保存报错），不会写坏数据；集群部署时 synchronized 完全失效。
- **修复建议：** 去 synchronized，改原子累加（`UPDATE ... SET current_seq = current_seq + 1 WHERE rule_code=?` 后回查）或 SELECT ... FOR UPDATE。

### P1-B：种子 SQL 重跑会重置流水号（2 视角共识：研发2号/测试1号）
- **位置：** `db/V1.8.0__mes_code_rule_init.sql`（SO/PO/MO 段）、`db/V9.5.0__mes_code_rule_biz_type.sql`（DN..PI 段）
- **机理：** DELETE+INSERT 保幂等的副作用是流水号归零。本次部署已实际发生（PO 0002→0001，当天无真实单据未造成事故）。
- **修复建议：** 改 `INSERT IGNORE` + 固定 id（如 `mes_code_rule_SO`），流水归运行数据自持。
