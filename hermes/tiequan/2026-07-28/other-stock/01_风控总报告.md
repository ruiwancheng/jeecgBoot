# 01_风控总报告 — MES 其它出入库审计

> 审计范围：Controller×2, Entity×4, Mapper×4, ServiceImpl×2, Vue×10, SQL×2
> 10 Agent 并行审计 | 共识规则：≥2 Agent → 高危必改

## 共识风险（≥2 Agent 检出，按严重度排序）

### 🔴 P0 共识（4 项，阻断发布）

| # | 问题 | 检出 Agent | 说明 |
|---|------|-----------|------|
| **P0-1** | **库存主表金额未更新** (`upsertWithDelta` 无金额参数) | 产品3号, 测试4号 | `stockIn`/`stockOut` 正确传了金额但 `upsertWithDelta` 只更新 `currentQty`，库存表金额字段从未被写入。任何"库存金额总计"查询返回 0 或脏数据。 |
| **P0-2** | **台账 `beginningAmount`/`endingAmount` 固定为 0** | 产品3号, 测试4号 | `MesInventoryServiceImpl.writeLedger` 两行 TODO 确认未实现。台账金额链在期初期末断裂，无法推算任意时点库存余额。**平台级（basic 模块），非 stock 引入。** |
| **P0-3** | **`amount`/`total_amount` 精度 DECIMAL(18,2) 不足** | 产品3号, 研发2号 | `qty DECIMAL(18,4) × unit_cost DECIMAL(18,4)` = 最高 8 位中间精度 → `.setScale(2)` 截断。多行合计舍入误差累积，对账时逐行 `qty×unitCost ≠ amount`。 |
| **P0-4** | **`audit()` TOCTOU — 审核生效明细可能过期** | 测试2号, 研发3号* | `queryWithItems` 不加锁 → 另一个事务的 `updateWithItems` 可在 `auditWithGuard` 前修改明细 → CAS 通过（status 仍 '1'） → `stockIn`/`stockOut` 使用旧 qty/unitCost/amount。修复：`audit()` 中 `queryWithItems` 改用 `selectByIdForUpdate`。 |

*研发3号原判 P2（"冗余查询"），经交叉分析确认为 P0（可导致数据错误）。

### 🟠 P1 共识（2 项）

| # | 问题 | 检出 Agent | 说明 |
|---|------|-----------|------|
| **P1-1** | **反审核库存不足死锁** | 产品2号, 研发3号 | 入库审核→库存+10→销售出库消耗8→库存剩2→反审核入库需回冲10→`stockOut` 抛"库存不足"→反审核失败→单据永远"已审核"。需要业务决策：允许负库存/标记待处理/提示补库存。 |
| **P1-2** | **`unaudit()` 同 `audit()` 的 TOCTOU** | 测试2号, 研发3号 | 当前设计中 `updateWithItems` 守卫阻止了已审核单据被编辑，但防御依赖状态而非锁——如果未来引入超级管理员强制编辑或直接 SQL 修改，`unaudit` 也会用过期明细回冲。加固建议同 P0-4。 |
