# 12_测试牛马4号_资损对账专项

> 审计对象：MES 其它出入库模块
> 审计视角：金额一致性、库存准确性、对账逻辑、回写机制
> 审计日期：2026-07-28

## 金额流全链路追踪

### 链路：入库单审核 → 库存 + 台账

```
用户输入: qty=100, unitCost=5.00
    ↓
validate(): amount = 100 × 5.00 = 500.00 (setScale(2))
totalAmount = sum(逐行 amount) = 500.00
    ↓
auditWithGuard: status '1' → '2' (原子CAS)
    ↓
inventoryService.stockIn(materialId, warehouseId, qty=100, unitCost=5.00, amount=500.00, "其它入库", code)
    ↓
MesInventoryServiceImpl.stockIn:
    - selectForUpdate: 获取库存快照
    - upsertWithDelta: current_qty += 100
    - writeLedger: inAmount=500.00
```

### 金额字段落库验证

|------|-----|------|--------|:--:|
| 验证 | c_mes_other_stock_in_item | amount | 500.00 | ✅ |

### 🔴 P0：库存主表金额字段未更新

`upsertWithDelta` 签名：

```java
int upsertWithDelta(String id, String materialId, String warehouseId,
    BigDecimal currentQty, BigDecimal delta,
    String createBy, String updateBy);
```

**没有任何金额参数！** `stockIn` 和 `stockOut` 调用时只传了数量和操作人：

```java
inventoryMapper.upsertWithDelta(id, materialId, warehouseId, before, qty, username, username);
//                                                                          ^ only qty
inventoryMapper.upsertWithDelta(id, materialId, warehouseId, before, qty.negate(), username, username);
//                                                                          ^ only delta
```

**后果链：**
1. 入库 100 件 × ¥5.00 → 库存 `current_qty` 增加 100 ✅，但库存金额**未变** ❌
2. 任何查询库存金额的 API → 返回 0（或旧值）
3. 财务报表取库存余额 → 与实际库存价值不符
4. 审计对账：入库总金额 ≠ 库存余额变化 → **业财数据断裂**

**修复紧急度：** 库存金额属于财务核心数据，必须修复。在 `upsertWithDelta` 中加金额字段，或在 `stockIn`/`stockOut` 后单独 UPDATE 金额。

### 🔴 P0：台账 beginningAmount / endingAmount 固定为 0

```java
ledger.setBeginningAmount(BigDecimal.ZERO);  // TODO Phase2
ledger.setEndingAmount(BigDecimal.ZERO);     // TODO Phase2
```

**影响：** 
- 台账的 `beginningAmount` 和 `endingAmount` 永远为 0
- 无法从台账推算任意时点的库存金额余额
- 财务报表需要额外计算（从台账的 `inAmount`/`outAmount` 重算期初期末）
- 如果台账记录有缺失，期初期末金额就无法恢复

**但注意：** 这和 stock 模块的 P0 不同——**这是 `MesInventoryServiceImpl` 的 P0（`basic` 模块）**，不是 stock 模块引入的。stock 模块作为调用方，正确传递了金额参数。台账金额未赋值是库存模块的问题。

**归类：** 平台级（跨模块）。不影响 stock 模块质量评级。但需要在审计报告中列示。

## 对联（cross-module reconciliation）

| 对账关系 | 状态 | 说明 |
|---------|:--:|------|
| 入库单金额 ↔ 库存金额增加 | 🔴 | 库存金额未更新（P0） |
| 入库单金额 ↔ 台账 inAmount | ✅ | stockIn 调用正确传参 |
| 出库单金额 ↔ 库存金额减少 | 🔴 | 库存金额未更新（P0） |
| 出库单金额 ↔ 台账 outAmount | ✅ | stockOut 调用正确传参 |
| 台账 inAmount ↔ 台账 beginning/ending | 🔴 | 期初期末固定为 0（P0, 平台级） |
| 库存数量 ↔ 台账数量 | ✅ | 正确的 FOR UPDATE 保障 |
| 单据总金额 = SUM(明细金额) | ✅ | validate() 中强制计算 |

## 结论

stock 模块自身金额计算和传递正确（`qty × unitCost → amount → totalAmount → stockIn/Out`）。但依赖的下游库存模块有两个 P0（库存主表金额未更新 + 台账期初期末固定为 0），导致业财不一致。stock 模块审计发现 1 个 P0（`amount` 精度 DECIMAL(18,2) 导致舍入误差）。

**风险汇总：2 P0（1 stock + 1 inventory）/ 0 P1 / 0 P2**
