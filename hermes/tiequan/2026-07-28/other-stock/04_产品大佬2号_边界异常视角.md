> 审计对象：MES 其它出入库模块
> 审计视角：并发安全、逆向操作、临界值、上下游联动
> 审计日期：2026-07-28

## 并发安全

### 审核并发 ✅

```sql
-- MesOtherStockInMapper.auditWithGuard
UPDATE c_mes_other_stock_in SET status='2' ... WHERE id=#{id} AND status='1'
```

- 原子 CAS 守卫：只有 status='1' 才更新为 '2'，返回值 0 时抛异常 ✅
- 先改状态再扣库存：副作用（`stockIn`/`stockOut`）在原子守卫成功后执行 ✅
- 无序依赖：先改状态成功 → 后扣库存，防止库存幻扣 ✅

### 反审核并发 ✅

```sql
UPDATE c_mes_other_stock_in SET status='1' ... WHERE id=#{id} AND status='2'
```

- 同样原子守卫：只有 status='2' 才可反审核 ✅
- 入库反审核 = stockOut 回冲，出库反审核 = stockIn 恢复 ✅

### 编辑并发 ✅

```java
// ServiceImpl.updateWithItems
MesOtherStockIn exist = baseMapper.selectByIdForUpdate(entity.getId());
```

- `FOR UPDATE` 行锁保护编辑操作，防并发修改 ✅

### 保存并发 ✅

- `catch DuplicateKeyException` + 软删除复活（借尸还魂模式）✅
- 唯一索引 `uk_other_stock_in_code_del (code, del_flag)` 数据库层兜底 ✅

## 逆向操作一致性

### 入库审核 ↔ 反审核回冲 ✅

| 操作 | 库存方向 | 调用 |
|------|---------|------|
| 入库审核 | 增加 | `stockIn(...)` |
| 入库反审核 | 减少 | `stockOut(..., "其它入库红冲", ...)` |

对称性：审核增加量 = 反审核减少量（使用同一明细的 qty/unitCost/amount）✅

### 出库审核 ↔ 反审核恢复 ✅

| 操作 | 库存方向 | 调用 |
|------|---------|------|
| 出库审核 | 减少 | `stockOut(...)` |
| 出库反审核 | 增加 | `stockIn(..., "其它出库红冲", ...)` |

对称性：审核扣减量 = 反审核恢复量 ✅

## 临界值

### 数量边界 ✅

```java
// validate: qty > 0
if (item.getQty() == null || item.getQty().compareTo(BigDecimal.ZERO) <= 0) {
    throw new JeecgBootException("第" + (i + 1) + "行数量必须大于0");
}
```

### 单价边界 ✅

```java
// validate: unitCost >= 0 (允许为null，null→BigDecimal.ZERO)
if (item.getUnitCost() != null && item.getUnitCost().compareTo(BigDecimal.ZERO) < 0) {
    throw new JeecgBootException("第" + (i + 1) + "行成本单价不能为负数");
}
```

### 库存不足拦截 ✅

```java
// MesInventoryServiceImpl.stockOut
if (before.compareTo(qty) < 0) throw new JeecgBootException("库存不足：...");
```

### 🟡 临界问题

| # | 问题 | 影响 | 等级 |
|---|------|------|:--:|
| B-1 | **入库反审核时库存不足不会抛异常**（`stockOut` 会抛，但无人拦截 → 审核态单据无法回退） | 如果入库后库存被其他出库单消耗到0，反审核入库时 `stockOut` 报"库存不足" → 反审核失败 → 单据锁死在已审核状态 | 🟠 P1 |
| B-2 | **金额精度不一致**：`unitCost DECIMAL(18,4)` 4位，但 `amount DECIMAL(18,2)` 仅2位，计算中间精度丢失风险 | 多行多物料大批量时，`totalAmount` 与各明细 `amount` 之和存在尾差（已通过逐行 setScale(2) 限定，但舍入误差累积不可避免） | 🟡 P2 |
| B-3 | **stockDate 无晚于当前日期的校验** | 可录入未来日期，审核时按实际日期生效 → 可能造成库存日期回溯（会计合规风险） | 🟡 P2 |

## 上下游联动

### 依赖关系 ✅

```
stock → inventory (库存增减) ✅
stock → inventory_ledger (台账) ✅
stock → code_rule (编码) ✅
stock ← warehouse (仓库下拉) ✅
stock ← material (物料选择) ✅
```

### 🟡 联动缺口

| # | 问题 | 影响 | 等级 |
|---|------|------|:--:|
| B-4 | **入库/出库未校验物料是否存在且启用** | 选择已禁用或已删除的物料，审核时库存会按无效物料扣减 → 库存表出现孤立物料记录 | 🟡 P2 |
| B-5 | **入库/出库未校验仓库是否启用** | 选择已停用的仓库，审核时库存会写入无效仓库 | 🟡 P2 |

## 结论

并发守卫设计到位（CAS + FOR UPDATE），审核/反审核对称性好。1 个 P1（反审核库存不足死锁）、4 个 P2。

**风险汇总：0 P0 / 1 P1 / 4 P2**
