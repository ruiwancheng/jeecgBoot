# 03_产品大佬1号_客户视角审计

> 审计对象：MES 其它出入库模块 (`stock/other-in`, `stock/other-out`)
> 审计视角：正向业务流程完整性、操作习惯贴合度
> 审计日期：2026-07-28

## 正向流程验证

### 1. 其它入库流程 ✅

```
新增入库单 → 填写头(单号/类型/仓库/日期/原因) → 填写明细(物料×N+数量+成本单价) → 保存 → 审核 → 库存增加
```

- 单号由编码规则自动生成（`getNextCode(QI)`），业务人员无需手工输入 ✅
- 入库类型字典已注册（盘盈/期初/归还/其他）✅
- 仓库下拉用 ApiSelect 从 `c_mes_warehouse` 动态加载 ✅
- 明细支持逐行添加、批量添加物料（MaterialSelectModal）✅
- 成本单价手工录入，金额自动计算（`qty × unitCost`，四舍五入 2 位）✅
- 审核后 `inventoryService.stockIn()` 即时更新库存 ✅

### 2. 其它出库流程 ✅

```
新增出库单 → 填写头(单号/类型/仓库/日期/原因) → 填写明细(物料×N+数量+成本单价) → 保存 → 审核 → 库存扣减
```

- 出库类型字典已注册（盘亏/报废/领用/其他）✅
- 审核时 `inventoryService.stockOut()` 内置库存不足拦截 ✅
- 反审核对称红冲（出库反审核 = stockIn 恢复库存）✅

### 3. 反审核流程 ✅

```
已审核单据 → 反审核 → 状态回退到草稿 → 库存反向冲回
```

- 入库反审核 = `stockOut` 回冲库存 ✅
- 出库反审核 = `stockIn` 恢复库存 ✅
- 原子守卫（WHERE status='2'）防并发 ✅

### 4. 批量操作

- 列表页支持多选 → 批量审核/批量反审核 ✅
- 但批量审核是**逐条串行调 API**，N 条单据 = N 次 HTTP 请求 🟡

## 客户操作体验评估

### 🟢 做得好的

1. **单号自动生成**：Drawer 打开时自动调 `getNextCode`，失败则回退手工输入，不阻塞开单
2. **批量添加物料**：支持 MaterialSelectModal 批量选物料，不是一行一行手动加
3. **行内金额实时计算**：`calcAmount` 计算属性实时显示 `qty × unitCost`
4. **编辑/删除只在草稿状态可用**：菜单动态隐藏，减少误操作

### 🟡 体验改进

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 1 | **已审核单据只有编辑/删除按钮**，没有单独的「反审核」按钮 | 用户需要勾选多条 → 点击反审核才能撤销，不够直接 | 操作列加「反审核」按钮（仅在已审核状态显示） |
| 2 | 总金额在列表和表单中**仅显示数字，无千分位格式** | 大金额时可读性差 | 前端 totalAmount 列用 `customRender` 格式化，如 `¥1,234.56` |
| 3 | 新增时 `items` 默认 `[{ qty: 1, unitCost: 0 }]`，unitCost 默认为 0 | 用户可能忘记填单价就提交→amount=0静默通过 | 改为 `unitCost: null`（不设默认值），让用户被迫填写 |

## 结论

出入口流程完整、状态流转清晰，核心业务路径无断裂。3 个体验级建议见上表。
