## 攻击面分析

### API 参数注入

| 攻击向量 | 防御 | 状态 |
|---------|------|:--:|
| POST /add → body 含 `status='2'` | `entity.setStatus("1")` 覆盖（L60） | ✅ |
| PUT /edit → body 含 `status='2'` | `entity.setStatus(null)` + `exist.getStatus()`守卫（L98） | ✅ |
| PUT /edit → body 含 `snapshotTime='hacked'` | `entity.setSnapshotTime(null)` 置空 | ✅ |
| POST /add → body 含 `items[].diffQty=99999` | `calcAndSaveItems` 重新计算 diff（L236），覆盖前端传值 | ✅ |
| PUT /audit?id=not-exist | `selectByIdForUpdate` → null → 抛异常 | ✅ |
| POST /add → body 含 `items[].generatedInId='steal'` | `item.setId(null)` 清空 id → 重新插入 → generatedInId 从 DB 覆盖 | ⚠️ 不全清 |

### 🔴 P1：`calcAndSaveItems` 未清除 `generatedInId`/`generatedOutId`

```java
// L230:
item.setId(null);  // ← 只置空了 id
item.setTakeId(entity.getId());
item.setLineNo(ln++);
// ← generatedInId 和 generatedOutId 未被置空！
```

**攻击向量：** 编辑盘点单时，前端传 `items[].generatedInId='malicious_value'` → 后端不清空 → 插入数据库 → 显示时展示伪造的关联单据号。

**影响：** 低（只是关联链接错误，不导致资损/库存改变）。审核后会被 `audit()` 中的 `updateById(item)` 覆盖。

**修复：** 加 `item.setGeneratedInId(null); item.setGeneratedOutId(null);`

### 🔴 P0：格式错误/SQL 注入
全 SQL 参数化，无 `${}` → ✅

### 前端攻击面

```typescript
// StocktakeDrawer L94-95: addLine()
if (!wh) { message.warning('请先选择仓库'); return; }
items.value.push({ materialId: '', bookQty: 0, actualQty: null, unitCost: 0 });
```
- `bookQty: 0` — 抽盘时用户未选物料前 book_qty 为 0，如果直接提交后端会接受 → diffQty = actualQty - 0 → diffQty 被放大
- 但 `onMaterialChange` 会在选物料时覆盖 bookQty ✅

### 🔴 P2：`pageSize=1` 的 inventory 查询取数不靠谱
```ts
const res: any = await queryInventoryList({ materialId: matId, warehouseId: wh, pageNo: 1, pageSize: 1 });
const row = res?.records?.[0];
```
- 如果同一物料在两个仓库→只取第一条 → bookQty 可能取到另一个仓库的库存 ❌
- `warehouseId` 参数已在 filter 中 → 实际只返回该仓库的那一行 ✅（inventory 的 API 按 warehouse 过滤）

但 `pageSize=1` 仍不保险 — 如果 inventory API 返回多行（同物料多个库位），只取第一行可能不对。✅ 当前库存表按 material+warehouse 唯一，一行就是正确的。

## 反审核缺失 🔴 P1

**盘点单没有 `unaudit` 端点。** 这是 V1 设计决策（不做红冲）。但：

1. 审核后无法回退 — 审核发现填错 → 必须手动建盘盈入库单对冲
2. 其他模块（OtherStockIn/Out）都有 `unaudit`
3. 生成的出/入库单有 `unaudit` 端点，但盘点单无法调
4. 如果盘点审核生成 30 行差异的出/入库单，用户需要反审核 1 张出库单 + 1 张入库单 → 但盘点单仍是"已审核"状态 ❌

**建议：** V1.1 加 `unaudit`，链式反审核（盘点 → 出入库单 → 库存回冲）。

## 结论
1 P0（calcAndSaveItems 不清空 generatedIn/OutId）、1 P1（反审核缺失）、2 P2。
