## 金额流全链路

### 差异化金额计算

```java
// calcAndSaveItems L236-238:
BigDecimal diff = item.getActualQty().subtract(item.getBookQty());
item.setDiffQty(diff);
item.setDiffAmount(diff.multiply(cost).setScale(2, RoundingMode.HALF_UP));
```

- diffQty DECIMAL(18,4) × unitCost DECIMAL(18,4) → diffAmount DECIMAL(18,2) ✅
- setScale(2) 舍入合理 ✅

### 生成入库单的金额传递

```java
// audit() L162-163:
ii.setQty(item.getActualQty().subtract(item.getBookQty()));
ii.setUnitCost(item.getUnitCost());
ii.setAmount(ii.getQty().multiply(item.getUnitCost() != null ? item.getUnitCost() : BigDecimal.ZERO)
    .setScale(2, RoundingMode.HALF_UP));
```

**注意：** 入库单的 `amount` 在盘点 `audit()` 中计算 → `saveWithItems(inDoc)` → `validate()` 中**重新计算 `amount`**：

```java
// MesOtherStockInServiceImpl.validate() L172-173:
BigDecimal cost = item.getUnitCost() != null ? item.getUnitCost() : BigDecimal.ZERO;
item.setAmount(item.getQty().multiply(cost).setScale(2, java.math.RoundingMode.HALF_UP));
```

**如果盘点 audit 和 OtherStockIn validate 的舍入不一致 → 以 validate 为准（后者覆盖前者）。** 两者都用 `HALF_UP, scale=2` — 一致 ✅


### 成本联动验证

**盘盈行：** 盘点审核 → 生成入库单 → OtherStockInService.audit → `updateMovingAvgCostOnStockIn(materialId, qty, unitCost, ...)` — 盘盈按均价入账 → avg 不变 ✅

**盘亏行：** 盘点审核 → 生成出库单 → OtherStockOutService.audit → 直接 `stockOut(...)` 无成本联动 — 出库不改变移动平均 ✅

### 🟡 差异金额合计字段更新方式

```java
// calcAndSaveItems L243-244:
entity.setTotalDiffAmount(totalDiff);
baseMapper.updateById(new MesStocktake().setId(entity.getId()).setTotalDiffAmount(totalDiff));
```

**问题：** `updateById` 更新整个 entity → 如果 `new MesStocktake()` 只设了 `id`+`totalDiffAmount`，其他字段全为 null → MyBatis-Plus 默认**策略**：null 字段**不更新**（`FieldStrategy.NOT_NULL`）→ 只有 totalDiffAmount 被更新 ✅

实际上这没问题，但实现方式不直观 — 用 Mapper `@Update` 注解更清晰（单字段更新）。🟡 P2

## 资损对账

| 对账关系 | 验证方法 | 状态 |
|---------|---------|:--:|
| 盘点 diffAmount 合计 = totalDiffAmount | `calcAndSaveItems` 逐行累加 | ✅ |
| 入库单 amount(盘盈) = 盘点明细 diffQty×unitCost | 两者在同一事务、同一 unitCost 快照 | ✅ |
| 出库单 amount(盘亏) = 盘点明细 |diffQty| × unitCost | 同上 | ✅ |
| 库存增减量 = 出入库单审核量 | 调用 OtherStockIn/Out.audit → stockIn/Out 内部正确 | ✅ (继承) |

## 结论
金额链传递一致（盘点 → 出入库单 → 库存+台账）。无新增 P0（盘点自身的金额逻辑正确，依赖的 OtherStockIn/Out 已验证）。1 P2（updateById 非最清晰）。
