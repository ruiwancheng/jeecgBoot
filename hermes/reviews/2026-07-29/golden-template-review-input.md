# 前端黄金模板体系 plan 评审输入（2026-07-29）

## 背景
JeecgBoot 平台代码生成（/new-module、jeecg-codegen）产出的是基础版页面，UX 优化（复选框、明细子表、批量添加、下拉搜索等）都要人工后补。最近手工做的 3 个页面（其它入库/出库/盘点单）已进化出成熟模式但没固化。用户诉求：生成页面时用一套成熟模板，不要一遍遍补体验优化；同时要能主动生成、能在线预览模板效果、后期可扩展新模板变体。

## 草案（plan）

### ① 黄金模板文件 harness/templates/mes-doc-page/
从其它入库/出库/盘点单提炼，占位符 {{MODULE}}/{{BIZ}}/{{TITLE}}，内置 10 个 UX 模式：
1. 搜索区字典下拉+仓库ApiSelect 2. 复选框+批量审核(状态守卫) 3. 明细子表展开行 4. 抽屉+自动编码接线(bizCodeMap) 5. 明细行编辑(物料选择+数量单价+金额自动算) 6. 批量添加物料弹窗+成本预填 7. 审核/反审核/删除状态机按钮 8. 快照/口径Alert提示 9. 差异红标高亮 10. 删除popConfirm+操作列守卫

### ② 主动命令 /new-page
`/new-page stock transfer-in 调拨入库` → 复制模板替换占位符 → 输出后续清单（后端4件套/菜单Registry/bizCodeMap/测试三件套/SQL）。/new-module 前端部分指向此模板（一处维护）。

### ③ 模板展示页 /project/mes/dev/template-gallery
纯前端 demo 页（无后端依赖，内置演示数据），10 个模式全部可点可玩。用途：用户预览模板效果、后期模板变体对比、AI 生成时的活标准答案。

### ④ frontend.md 补「单据页 UX 基线」清单
铁拳团产品 agent 按清单查漏，防生成时模式漂移。

## 待评审问题
1. 模板用"占位符字符串替换"生成（{{MODULE}} 全局替换）vs 用 AST/结构化生成？前者简单但可能误替换（比如注释里的占位符、大小写变体 Module/module/MODULE 多套占位符），后者复杂。占位符规范怎么定最稳？
2. Gallery 展示页用纯前端假数据（无后端）vs 接一个真实 demo 实体？假数据零依赖但展示不了"真实接口交互"（如批量添加弹窗要拉物料列表——弹窗组件 MaterialSelectModal 内部调真实物料接口，这算不算破坏了"无后端依赖"的设计？）
3. 10 个模式全塞进一个模板，会不会导致"简单页面被迫背重模式"（比如纯列表页不需要明细子表）？要不要分 单表版/主子表版 两个模板？（现有 /new-module 就是分单表/主子表的）
4. 模板放 harness/templates/ 还是放 src/views/ 下作为可运行代码？放 harness 不参与构建（纯文本模板），放 src 下则 Gallery 可以直接 import 模板文件本身（模板即展示页，一处代码两用）——后者会不会更好？但模板含占位符不能直接编译。
5. /new-page 与现有 /new-module 的边界：/new-module 生成前后端全套，/new-page 只生成前端？还是应该把 /new-module 升级吞掉 /new-page？两个命令并存会不会又像 /test-loop 那样制造混乱？
6. 有没有遗漏？比如：模板的版本演进怎么管（模板改了，已生成的页面要不要跟）？i18n/权限码/菜单注册的自动化程度？
